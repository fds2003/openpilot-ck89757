## 1. 背景与攻坚痛点

### 1.1 需求目标
为官方高德地图车机版 9.1.0 添加「**原包名悬浮窗**」功能：
- 保持官方包名 `com.autonavi.amapauto`，支持与车机系统、原厂面板数据无缝衔接。
- 退到后台时在车机桌面（Launcher）显示微型导航悬浮窗。
- 支持车机广播（`com.autonavi.plus.showmap` / `closemap`）显示与隐藏。

### 1.2 历史教训：为什么 7.5.0 的修改方式在 9.1.0 上彻底失效？
在早期的 4 次移植尝试中，照搬 7.5.0 靓华版的做法（仅注入 `libtouka.so` 并将 Java 层校验类 `b90.smali` 或 `Sign.smali` 改为 `return true`），实测结果全部为**启动后黑屏**。

| 对比维度 | 7.5.0 机制 | 8.5.0 / 9.1.0 机制 | 移植 7.5.0 方式到 9.1.0 的后果 |
|---|---|---|---|
| **校验层级** | 仅 Java 层（`l90.d` 校验） | **Java + Native 双重校验** | Java 层强行改 true，native 层得不到真实签名哈希 |
| **底层拦截点** | 无底层检测 | `libGFrame.so` 等通过 JNI / 反射 / 读取 APK 校验 | 3D 渲染引擎拒绝初始化（Logcat 无 `InitEgl`） |
| **现象** | 正常渲染 | 正常启动、Activity 存活，但**地图区域全黑** | **黑屏不可用** |

## 2. 8.5.0 靓华方案技术架构拆解

8.5.0 靓华版能够成功的核心在于其**放弃了破坏业务代码**，转而采用了 **ApkSignatureKillerEx（双层运行时签名欺骗）+ 第二代 ToukaFloatPlugin 悬浮插件** 的组合方案。

```
┌────────────────────────────────────────────────────────────────────────┐
│                   应用进程启动 (MapApplicationProxy)                   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 继承触发
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│              支柱一：ApkSignatureKillerEx 运行时签名欺骗                │
│                                                                        │
│  1. Java 层拦截 (killPM)：                                             │
│     反射替换 PackageInfo.CREATOR 包装器。                               │
│     所有 PackageManager 签名查询均返回硬编码的官方 MINIMAP 证书 DER。  │
│                                                                        │
│  2. Native 文件拦截 (killOpen)：                                       │
│     加载 libSignatureKiller.so (基于爱奇艺 xHook 1.2.0)。               │
│     Hook libc 的 open/openat 系统调用。                                │
│     Native 库尝试通过路径读取 base.apk 校验时，重定向到 origin.apk。   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 构造完成进入 onCreate()
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│              支柱二：第二代原生悬浮插件 ToukaFloatPlugin v2              │
│                                                                        │
│  1. FloatPlugin.create(Application) 注册 ActivityLifecycleCallbacks。 │
│  2. 监听 MainMapActivity 生命周期：后台显示悬浮窗，前台自动回收。      │
│  3. 加载 libToukaFloatPlugin.so，管理 FrameLayout + SurfaceView 挂载。 │
│  4. 注册 FloatReceiver 接收 com.autonavi.plus.showmap/closemap 广播。  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│              支柱三：业务类零篡改原则                                    │
│                                                                        │
│  9.1.0 官方 Sign.checkSign() 原版即返回 true，不修改 Sign.smali 和      │
│  b90.smali，避免引入额外异常。                                         │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. 9.1.0 移植实施全流程

### 3.1 移植材料清单

所有移植组件均从 `高德地图车机版8.5.0.600050悬浮(靓华修改).apk` 提取：

| 组件类别 | 路径 / 文件 | 大小 | 作用 |
|---|---|---|---|
| **Smali 源码** | `smali/bin/mt/signature/*` (5 个类) | ~30 KB | 签名 Hook 入口、CREATOR 代理 |
| **Smali 源码** | `smali/org/lsposed/hiddenapibypass/*` (9 个类) | ~25 KB | 高版本系统 Hidden API 豁免（老系统安全静默） |
| **Smali 源码** | `smali/tech/touka/floatplugin/*` (5 个类) | ~15 KB | 第二代悬浮窗 Java 接口与广播类 |
| **Native 动态库** | `lib/armeabi-v7a/libSignatureKiller.so` | 30,768 B | xHook 底层文件系统重定向库 |
| **Native 动态库** | `lib/armeabi-v7a/libToukaFloatPlugin.so` | 134,708 B | 悬浮窗核心逻辑与视图搬运库 |
| **Asset 资源** | `assets/SignatureKiller/origin.apk` | 22,989 B | 包含合法正版签名的占位空壳 APK |

### 3.2 步骤概览
1. **反编译 9.1.0 源码**：使用 `apktool d` 解码官方原版。
2. **植入 Smali 模块**：复制 `bin/`、`org/`、`tech/` 目录。
3. **篡改 Application 基类**：修改 `MapApplicationProxy.smali`。
4. **编译 Classes.dex**：解决资源与 Dex 编译。
5. **注入官方基础包**：使用官方原版资源骨架，仅替换 Dex、注入 So 和 Asset（避免全量资源重编导致的体积膨胀和兼容性隐患）。
6. **对齐与签名**：使用 `uber-apk-signer` 及 Platform 密钥签名。

## 4. 核心代码与注入改动细节

### 4.1 `MapApplicationProxy.smali` 关键修改点

文件路径：`smali/com/autonavi/amapauto/app/MapApplicationProxy.smali`

#### 修改点 1：父类继承修改
```diff
 .class public Lcom/autonavi/amapauto/app/MapApplicationProxy;
-.super Landroid/app/Application;
+.super Lbin/mt/signature/KillerApplication;
 .source "MapApplicationProxy.java"
```

#### 修改点 2：构造函数父类调用
```diff
 .method public constructor <init>()V
     .locals 1
 
     .line 1
-    invoke-direct {p0}, Landroid/app/Application;-><init>()V
+    invoke-direct {p0}, Lbin/mt/signature/KillerApplication;-><init>()V
 
     const/4 v0, 0x1
```

#### 修改点 3：`onCreate()` 注入悬浮插件
在 `onCreate()` 方法中，紧随 `invoke-super` 之后添加一行启动调用：
```diff
 .method public onCreate()V
     .locals 6
     const-string v0, "call application method onCreate failed"
     const-string v1, "DexTrace.MapApplicationProxy"
 
     .line 1
     invoke-super {p0}, Landroid/app/Application;->onCreate()V
+
+    invoke-static {p0}, Ltech/touka/floatplugin/FloatPlugin;->create(Landroid/app/Application;)V
 
     const/4 v2, 0x0
```

### 4.2 为什么必须清理老版 `tech/touka/plugin/amap`？
若此前工程中残留有第一代插件代码（`FloatPluginManager` / `ControlReceiver`），必须彻底删除，仅保留第二代 `tech/touka/floatplugin`，避免双广播接收器或类冲突。

## 5. 自动化移植脚本

为了确保打包过程可完全复现，并保持官方原版资源的最佳压缩率（避免 apktool 重建后从 130MB 膨胀到 225MB），采用 **“Smali 编译 Dex + Python 原包精确组装 + Uber-Apk-Signer 签名”** 流程。

### `package_port.py`
```python
import os
import shutil
import zipfile
import subprocess

SRC_APK = r"E:\汽车\车机应用\高德地图车机版\Auto_9.1.0.600087_release_signed.apk"
NEW_DEX = r"D:\Temp\amap910-check\classes_910_v85method.dex"
OUT_UNSIGNED = r"D:\Temp\amap910-check\Auto_9.1.0_v85method_final_unsigned.apk"
OUT_DIR = r"D:\Temp\amap910-check\signed-v85method"
FINAL_APK = r"E:\汽车\车机应用\高德地图车机版\Auto_9.1.0.600087_原包名悬浮_8.5靓华方案移植版.apk"

UBER_SIGNER = r"D:\Temp\apksigner-tool\uber-apk-signer.jar"
PLATFORM_KEY = r"D:\Temp\amap910-check\aosp-key\platform.p12"

EXTRA_FILES = [
    (r"D:\Temp\amap910-check\v85lh\lib\armeabi-v7a\libSignatureKiller.so", "lib/armeabi-v7a/libSignatureKiller.so"),
    (r"D:\Temp\amap910-check\v85lh\lib\armeabi-v7a\libToukaFloatPlugin.so", "lib/armeabi-v7a/libToukaFloatPlugin.so"),
    (r"D:\Temp\amap910-check\v85lh\assets\SignatureKiller\origin.apk", "assets/SignatureKiller/origin.apk"),
]

def build_package():
    print("[1/3] Packaging raw APK with new Dex & injected libraries...")
    with open(NEW_DEX, "rb") as f:
        dex_data = f.read()

    zin = zipfile.ZipFile(SRC_APK, "r")
    zout = zipfile.ZipFile(OUT_UNSIGNED, "w", zipfile.ZIP_DEFLATED)

    for item in zin.infolist():
        name = item.filename
        if name == "classes.dex":
            zout.writestr("classes.dex", dex_data)
        elif name.startswith("META-INF/") and name.endswith((".RSA", ".SF", ".MF", ".DSA", ".EC")):
            continue  # 剥离旧签名
        else:
            zout.writestr(item, zin.read(name))

    for src_path, arc_name in EXTRA_FILES:
        with open(src_path, "rb") as f:
            zout.writestr(arc_name, f.read())

    zin.close()
    zout.close()
    print(f" -> Raw package generated: {os.path.getsize(OUT_UNSIGNED)} bytes")

    print("[2/3] ZipAligning and Signing with Platform key...")
    cmd = [
        "java", "-jar", UBER_SIGNER,
        "-a", OUT_UNSIGNED,
        "--ks", PLATFORM_KEY,
        "--ksAlias", "platform",
        "--ksPass", "android",
        "--ksKeyPass", "android",
        "-o", OUT_DIR
    ]
    subprocess.run(cmd, check=True)

    print("[3/3] Exporting final product...")
    signed_name = os.path.basename(OUT_UNSIGNED).replace(".apk", "-aligned-signed.apk")
    signed_path = os.path.join(OUT_DIR, signed_name)
    shutil.copy2(signed_path, FINAL_APK)
    print(f" -> Completed! Output: {FINAL_APK} ({os.path.getsize(FINAL_APK)} bytes)")

if __name__ == "__main__":
    build_package()
```

## 7. 车机实装注意事项与风险预案

### 7.1 车机环境兼容性分析
- **Android 版本**：4.4.3（API 19）。
- **Dex 结构**：本次生成的 `classes.dex` 仅 6.33 MB，方法数 46,208（< 65,536），为原生单 Dex 结构，**不需要 MultiDex**，在老旧 Dalvik 虚拟机上拥有极高的加载稳定性。
- **SO 架构**：`libSignatureKiller.so` 目标 API 为 17，`libToukaFloatPlugin.so` 目标 API 为 19，完全契合车机 API 19（armeabi-v7a）。

### 7.2 实车安装操作建议
1. **车机安装前备份**：备份当前车机中可正常使用的版本（例如 7.5.0 或 8.5.0 靓华版 APK 及 `/data/data/com.autonavi.amapauto` 数据）。
2. **签名覆盖问题**：若车机提示签名不一致无法覆盖，需先通过车机文件管理器（如 RootExplorer）备份数据后卸载旧版，再行安装本包。
3. **白名单配置**：确认车机桌面框架（`com.hsae.d531mc.launcher`）的 `assets/white.txt` 白名单中已包含 `com.autonavi.amapauto,com.autonavi.amapauto.MainMapActivity`。
4. **一键刷新包集成**：可直接将本 APK 替换到 `tools/components/` 对应安装目录，通过 `build.bat` 重新构建针对 SOC 的 `update.zip` 进行实车刷入。

## 8. 改动对功能与稳定性的影响深度评估

### 8.1 核心业务功能：零影响（Zero Tampering）
本次移植遵循“只伪造运行环境、不碰业务逻辑”的原则。除 Application 入口继承与悬浮窗生命周期注入外，未修改高德任何内部类：

| 核心功能模块 | 是否受影响 | 证据与机理 |
|---|---|---|
| **GPS 定位 / 惯导** | ❌ **无影响** | 定位服务直接对接系统 LocationManager 与车载 NMEA 协议，代码 100% 官方原版。 |
| **算路规划 / 实时路况** | ❌ **无影响** | 在线路况协议库（`libGNet.so` 等）与网络通信类未改动，正常与高德服务器交互。 |
| **3D 地图引擎渲染** | ❌ **无影响** | 底层 `libEGL`、`libGFrame.so` 渲染管线未动，Logcat 证实 `InitSurface` 上下文完整分配。 |
| **语音播报 / TTS** | ❌ **无影响** | 车载音频通道与 TTS 发音组件完全保持官方原样。 |
| **离线数据 / 账户同步** | ❌ **无影响** | 数据库与本地持久化逻辑未碰，离线地图下载与读取正常。 |

### 8.2 系统开销与性能表现
- **CPU 开销**：`libSignatureKiller.so` 仅挂钩 libc 的 `open`/`openat` 系统调用，只对以 `base.apk` 结尾的目标路径做重定向，开销在微秒级别，常规运行时 CPU 占用为 0%。
- **内存常驻**：Hook 库自身常驻内存 < 100 KB。悬浮窗在前台导航时不绘制、不占显存；仅在退至后台时复用 `SurfaceView` 渲染微型图层，额外内存增加仅数兆字节（与 8.5.0 靓华版完全相同）。

### 8.3 运行稳定性分析
1. **单 Dex 兼容优势**：
   本包生成为原生单 Dex 结构（`classes.dex` 6.33 MB，方法数 46,208，上限 65,536）。在老旧的 Android 4.4.3 Dalvik 虚拟机上，单 Dex 免去了 MultiDex 在启动阶段解压和安装 secondary dex 的性能损耗，彻底杜绝了由此引起的冷启动 ANR 或类加载失败。
2. **xHook 底层可靠性**：
   基于爱奇艺工业级成熟开源方案，仅在当前应用进程内进行 PLT/GOT 劫持，不向系统全局或其它进程注入，绝不影响车机系统本身的稳定性。
3. **悬浮窗三态原子锁**：
   第二代插件（`libToukaFloatPlugin.so` + `FloatWindow.smali`）引入了 3 个 `AtomicBoolean` 原子标志位（`isCreated`、`isShowingFloatWindow`、`canShowFloatWindow`），消除了老版在频繁切换前后台时偶发的窗口竞争与闪烁问题。

### 8.4 边界限制与使用避坑
1. **严禁应用内在线升级**：若在高德设置中点击在线升级并覆盖安装官方增量包，会导致签名冲突安装失败，或覆盖后悬浮窗代码被冲掉。车机端必须关闭自动更新，日后升级一律通过 USB 刷入。
2. **低内存清理机制（LMK）**：若车机同时多开过多占用内存的 App，系统底层触发 Low Memory Killer 杀死高德进程时，悬浮窗将随进程一同关闭（此为 Android 正常回收机制，重新点开高德即可恢复）。
