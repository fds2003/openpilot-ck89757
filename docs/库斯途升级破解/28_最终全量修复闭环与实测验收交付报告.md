## 一、五大阻断项 (Blocking Issues) 最终修复闭环对照

针对 26 号与 27 号独立审计报告所提出的全部阻断级问题，逐项落盘修复如下：

### 1.1 阻断项 P-1 (B-01)：端口交叉彻底消除“同向冲突”
* **问题机理**：上一轮车机端改为了 `PORT_TELEMETRY=7706 / PORT_CONTROL=7705`，而 C3 端的 `amap_navi.py` 却把 `navi_port=7705`、`navi_remote_port=7706`，导致两端都在 7705 听、往 7706 发，形成镜像同向冲突；
* **修复落地**：
  - **车机端 (`CarrotUdpClient.kt:31-32`)**：
    ```kotlin
    const val PORT_TELEMETRY = 7706 // 车机本地绑定监听端口 (接收 C3 遥测数据)
    const val PORT_CONTROL = 7705   // 对端 C3 监听端口 (车机向 C3 发控制指令)
    ```
  - **C3 端 (`amap_navi.py:200-201`)**：
    ```python
    self.navi_port = 7706        # C3 遥测【发送】目标端口 = 车机 PORT_TELEMETRY (7706)
    self.navi_remote_port = 7705  # C3 指令【接收】监听端口 = 车机 PORT_CONTROL (7705)
    ```
* **闭环矩阵**：
  $$\text{C3 发送目标 (7706)} \longrightarrow \text{车机监听接收 (7706)}$$
  $$\text{车机发送目标 (7705)} \longrightarrow \text{C3 监听接收 (7705)}$$
  两端完全交叉咬合，双向链路 100% 畅通！

### 1.2 阻断项 P-2 (B-02)：探针回包彻底杜绝“车机自发自收”
* **问题机理**：C3 5510/4210 探针响应线程在提取发送方 `addr[0]` 后，直接将 `ip: addr[0]` 塞入回包；车机收到后解析出自己的 IP，导致车机将指令发给自身，形成静默故障；
* **修复落地**：
  - **C3 端 (`amap_navi.py:617-626`)**：
    通过向接收到的 IP 发起瞬时本地路由探测（`s_tmp.connect((ip, 80))`），动态提取 C3 自身在当前局域网内的真实分配 IP（如 `192.168.43.128`），并在回包中准确填入：
    ```python
    c3_ip = ""
    try:
      with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as s_tmp:
        s_tmp.connect((ip, 80))
        c3_ip = s_tmp.getsockname()[0]
    except Exception:
      c3_ip = ""
    resp = json.dumps({"resp": "c3_pong", "device": "comma3", "status": "ready", "device_id": "c3", "auth": True, "ip": c3_ip, "version": "openpilot-cp-custo"}).encode('utf-8')
    ```
  - **车机端 (`UdpDeviceDiscovery.kt:128-137`)**：
    增加**双重防回弹防护**，优先采用 UDP 报文底层的物理源 IP（`packet.address.hostAddress`），且严格过滤 `127.0.0.1` 与自身 IP，确保解析到的目标绝无可能是车机自身。

### 1.5 阻断项 P-5 (F-03)：车机端距离量纲双重除法归一防护
* **问题机理**：C3 端发送的 `lb_drel` 已是米制浮点数（如 `12.5`），若车机端再次除以 1000 会变为 `0.0125` 米，导致车机净空门禁误判为后车贴身而永久阻断；
* **修复落地** (`CarrotTelemetryParser.kt:48-54, 123-124`)：
  ```kotlin
  private fun parseDistanceMeter(rawVal: Float): Float {
      if (rawVal <= -999000.0f || rawVal == 0.0f) return 999.0f
      val absVal = Math.abs(rawVal)
      // 若数值 > 100.0，说明是原始毫米单位 (如 12500mm)，需除以 1000 转换为米；
      // 若数值 <= 100.0，说明已经是米制单位 (如 12.5m)，直接采信，严防双重转换！
      return if (absVal > 100.0f) absVal / 1000.0f else absVal
  }
  ```
  在流式解析与 JSONObject 解析两个重载中统一步调，无论上游发送米制还是毫米制，统一输出准确正米制距离。
