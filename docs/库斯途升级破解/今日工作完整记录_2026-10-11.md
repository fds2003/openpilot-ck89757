## 5. SOC 绑定机制破解

### 5.1 完整链路

```
SOC (ro.boot.serialno)
  ├─ echo "$SOC" > serialno.txt     → SOC + "\n"
  ├─ MD5SUM   = md5(SOC + "\n")     → 7z 加密密码
  └─ SHA512SUM = sha512(SOC + "\n") → package/id 内容（校验）
```

### 5.2 关键数值（SOC = 201fb1d4d5ab9393）

| 项目 | 值 |
|------|-----|
| SOC | `201fb1d4d5ab9393` |
| 7z 密码 (md5) | `d4c39af5e2c09c93fa129925f7b63182` |
| id (sha512) | `70ff0505f744aa1d463b554bf0626f80b2784d7c7ccf63199781d7961d03ef6e1e889c8dbb1211345b811bcdbc46b3280fd07706893f92195b02ee5700c461c3` |

### 5.3 package.7z 格式细节

- 实际是 **zip 格式**（magic `504b0304`），非 7z 格式
- **AES-256 加密**（compress_type=99）
- 内部路径：`package/id`、`package/system/app/...`、`package/system/xbin/su`
- `id` 文件 = sha512 hex + `\n`（LF，**129 字节**）

### 5.4 换车要重新要 SOC 的原因

7z 密码和 id 校验都绑定 SOC 哈希，包锁死在单台车机上。

## 9. 踩坑记录

### 9.1 高德 APK 部分

| 问题 | 原因 | 解决 |
|------|------|------|
| apktool 重打包失败 | anims.xml 资源编译错误（aapt2 严格校验） | 改用「直接 patch 原 APK」：只替换 classes.dex + 加 so，再重签名 |
| package.7z 实际是 zip | 7z 命令 `Type=zip`，非 7z 格式 | 用 zip 工具解压 |

### 9.2 库斯途包部分

| 问题 | 原因 | 解决 |
|------|------|------|
| 7z 密码错误 | `echo` 追加 `\n`，md5 需算 SOC+"\n" | 用带换行符的 md5 |
| 7za 9.20 不支持 zip 密码 | 工具太老 | 用系统 7-Zip 26.04 + Python zipfile |
| Python zipfile 无法读 AES zip | 标准库只支持 ZipCrypto | 用 7z 命令解压 |
| 7z 打 zip 报"参数错误" | `-m0`（store）+ 大文件组合 bug | 去掉 `-m0`，或改 Python zipfile |
| 路径嵌套 `package/package/` | COMPONENTS rel 带 package 前缀 + 7z 目录处理 | rel 去前缀 + 用相对路径 cwd |
| id 文件 130 字节（应 129） | Python `write_text` Windows 把 `\n`→`\r\n` | 改用 `write_bytes` |
| 7z 格式 vs zip 格式 | 车机 7z 提取器只认 zip（magic 504b0304） | 用 `-tzip` 而非 `-t7z` |

### 9.3 环境问题

| 问题 | 解决 |
|------|------|
| `D:\Temp` 中文路径解析异常 | 用绝对路径 + cwd 参数 |
| winget 装 7-Zip 需管理员 | winget 成功（MSI 安装） |
| cmd 无法用 `7z` 命令 | 用完整路径 `C:\Program Files\7-Zip\7z.exe` |
