## 三、跨工程（双端）缺陷核验

跨工程报告《库斯途双工程协同分析报告》是这批文档里唯一真正有价值的，但其中 J-1 已部分过期，需按当前代码重判。

### J-1（原 P0 → 现降级 P1）"无数据"语义两端相反

**仍成立的部分**：
- [desire_helper.py:957-964](file:///E:/code/openpilot-ck89757/selfdrive/controls/lib/desire_helper.py#L957-L964)：`behind_ttc = lidarBehindVdistTime`，无数据时为 `0.0` → `rear_conflict = (behind_ttc <= 0.0)` → 置 `auto_lane_change_trigger=False`，**且**每 2 秒 `lane_change_audio(True, 6, 0)`（"后方来车"）。该分支在 `update()` 主干，**与是否有变道请求无关**——正常巡航也会每 2 秒播报。
- 车机侧缺键默认 999m → 判定"净空充足"放行。两端语义确实相反。

**已不成立的部分**：
- 原报告称"超时 → `FINISHING` → 播 `LANE_CHANGE_OK`（变道完成）"。当前 [OvertakeStateMachine.kt:245-254](file:///E:/%E6%B1%BD%E8%BD%A6/%E5%BA%93%E6%96%AF%E9%80%94%E5%8D%87%E7%BA%A7%E7%A0%B4%E8%A7%A3/AmapNavi-Reborn/app/src/main/java/tech/touka/amapnavi/domain/decision/OvertakeStateMachine.kt#L245-L254) 已改为"超时一律撤销 + 播 `LANE_CHANGE_CANCEL` + 长冷却"，假成功播报已消除。

**当前实际后果**：不再出现"假完成"，但仍存在"车机请求 → C3 静默阻断 + 双端语音互相矛盾 + 25s 循环请求"。因此从 P0 降为 P1，但必须修——**误播报会训练驾驶员忽略告警**。

**两点需澄清（与旧结论有出入）**：

1. **TTC 门禁并未被遥控路径旁路**。旧分析称车机指令可绕过 C3 的 TTC 检查，实码不成立：[desire_helper.py:956-964](file:///E:/code/openpilot-ck89757/selfdrive/controls/lib/desire_helper.py#L956-L964) 把 `rear_conflict` 写回 `auto_lane_change_trigger`，而 [L1162](file:///E:/code/openpilot-ck89757/selfdrive/controls/lib/desire_helper.py#L1162) 进入 `laneChangeStarting` 必需该 trigger，故遥控路径同样受 1.8/2.5/3.5s 档位约束。
2. **但车机侧这道门禁是另一套物理量**（见 #14）：C3 用 TTC，车机用距离门限 `max(10, v_ego/3.6*2.0)`，且缺键/真值 0 都当 999m 放行。所谓"双端门禁"实为两套不可比的判据，**没有一处是端到端生效的**。

### J-2（P0，仍成立）协议没有"被拒绝"状态

- 协议只有 `atc_state`（3=完成），无 `REJ_TTC / REJ_LINE / REJ_BSD / REJ_TIMEOUT`，也无请求 id 回显。
- 车机 `CarrotTelemetryParser` 未解析 `op_blocked` / `atc_type`，只能靠超时猜测结果。
- **建议**：`laneChangeStatus: 0=IDLE 1=PRE 2=EXEC 3=DONE 4=REJ_TTC 5=REJ_LINE 6=REJ_BSD 7=REJ_STATE 8=ABORT_DRV` + `reqId` 回显；车机 `EXECUTING` 只接受 DONE/REJ，任何超时记为 `REJ_TIMEOUT`，永不播成功音。

### 新增（比 J-1 更本质）双端"传感器缺失"默认值不一致

- C3：`sensor_ready=False` → `behind_ttc=0.0` → **恒阻断**。
- 车机：缺键 → `999.0m` → **恒放行**。
- 这意味着**未装 BSD/激光雷达的库斯途**上，自主变道功能永远走不通，且两端日志各说各话。必须在协议层定义统一的"不可用"值（建议 `null` + 显式 `ttcStatus`），而不是让两端各自猜。
