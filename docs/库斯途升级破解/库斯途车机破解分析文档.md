## 1. 高德地图 APK 修改

### 1.1 任务

### 1.2 参考版（靓华修改 7.5.0）逆向分析结果

修改内容非常精简，共 4 类：

**① 新增 6 个 smali 文件（Java 入口桩）**

| 文件 | 作用 |
|------|------|
| `tech/touka/plugin/amap/FloatPluginManager.smali` | 入口：`loadLibrary("touka")` + 单例初始化 |
| `tech/touka/plugin/amap/ControlReceiver.smali` | 广播接收器（`onReceive` 是 native 方法） |
| `touka/a.smali` | native 声明：`static native a(Application)` |
| `touka/b.smali` ~ `touka/d.smali` | native 声明壳 |

**② 唯一注入点** — `MapApplicationProxy.smali` 的 `onCreate()` 方法，`invoke-super` 之后插入一行：

```smali
invoke-static {p0}, Ltech/touka/plugin/amap/FloatPluginManager;->init(Landroid/app/Application;)V
```

**③ 新增 `libtouka.so`（悬浮窗核心逻辑全在此 native 库，约 133KB）**

- 仅 `armeabi-v7a`（32 位）架构
- 悬浮窗的实际实现（窗口管理、系统级悬浮）都在这个 so 里

**④ 签名替换为 `PLATFORM.RSA`（平台签名）**

- 原版签名：`MINIMAP_.RSA`
- 修改版签名：`PLATFORM.RSA`
- `SYSTEM_ALERT_WINDOW` 悬浮权限依赖平台签名才能被车机系统直接授予

## 2. 库斯途 update.zip 刷新包机制

### 2.1 外层结构

```
update.zip (OTA 格式，外层 zip 不加密)
├── META-INF/com/android/otacert          # OTA 证书
├── META-INF/MANIFEST.MF                  # 签名清单
├── META-INF/CERT.SF                      # 签名
├── META-INF/CERT.RSA                     # 签名证书
├── META-INF/com/google/android/update-binary   # AOSP 更新二进制
├── META-INF/com/google/android/updater-script  # 挂载 + 执行 install.sh
├── 7z                                     # ARM 32位 7-Zip 提取器
├── install.sh                             # 安装逻辑
└── package.7z                             # 加密负载（实际是 zip 格式）
```

### 2.2 install.sh 安装流程

1. 读取 `ro.boot.serialno` 得到 SOC
2. 计算 `MD5SUM = md5(SOC + "\n")`、`SHA512SUM = sha512(SOC + "\n")`
3. 用 `7z x -p$MD5SUM` 解包 `package.7z`
4. 校验 `package/id` == `SHA512SUM`，不符则中止
5. 安装 `su` + `daemonsu` 到 `/system/xbin/`（权限 6755）
6. 安装 5 个 APK 到 `/system/app/`（Launcher / Carlife / UsbMedia / RootExplorer）
7. 悬浮版额外写入 `license.bin` 到 `/system/`
8. 删除 `fire_wall_control.sh`（关防火墙）
9. 向 `yantu.sh` 追加开机脚本：
   ```sh
   # touka su script begin
   /system/xbin/daemonsu --auto-daemon &
   stop firewallcontrol
   touch /data/appdebug
   touch /sdcard/hbdisable
   # touka su script end
   ```

### 2.3 updater-script 流程

```
挂载 /system (ext4, EMMC, mmcblk3p5)
→ 提取 install.sh / 7z / package.7z 到 /tmp
→ 执行 install.sh
→ 卸载 /system
```

## 4. SOC 绑定与加密校验机制

### 4.1 完整链路

```
SOC 序列号 (ro.boot.serialno)
        │
        ├─ echo "$SOC" > serialno.txt   (内容 = SOC + "\n")
        │
        ├─ MD5SUM  = md5(SOC + "\n")    → 7z 加密密码
        │
        └─ SHA512SUM = sha512(SOC + "\n") → package/id 内容（校验用）
```

### 4.2 关键数值（本机 SOC = 201fb1d4d5ab9393）

| 项目 | 值 |
|------|-----|
| SOC | `201fb1d4d5ab9393` |
| 7z 密码 (md5) | `d4c39af5e2c09c93fa129925f7b63182` |
| id (sha512) | `70ff0505f744aa1d463b554bf0626f80b2784d7c7ccf63199781d7961d03ef6e1e889c8dbb1211345b811bcdbc46b3280fd07706893f92195b02ee5700c461c3` |

### 4.3 package.7z 格式细节

- **实际是 zip 格式**（magic `504b0304`，非 7z 格式）
- **AES-256 加密**（compress_type=99）
- 密码 = md5(SOC + "\n")
- 内部路径结构：`package/id`、`package/system/app/...`、`package/system/xbin/su`
- `id` 文件 = sha512 hex + `\n`（LF，129 字节）

### 4.4 换车就要重新要 SOC 的原因

对方每次给包都要 SOC，是因为 7z 密码和 id 校验都绑定 SOC 的哈希值，包被锁死在单台车机上。

## 8. 注意事项与风险

### 8.1 刷入前必须

1. **备份车机系统**（变砖无法启动的风险）
2. 运行 `verify_package.py` 确认 36 项全部通过
3. 确认 U 盘格式为车机可识别（FAT32 通常最稳）

### 8.2 已知风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| 变砖 | 刷新失败可能导致无法启动 | 备份 + 严格验证 |
| 签名不符 | 自签名非真正平台签名 | 车机可能拒刷或需降级 |
| SOC 不符 | 换车需重新打包 | 用新 SOC 重跑 build.bat |

### 8.3 自定义桌面版本的方法

1. 准备定制好的 `Launcher.apk`（必须 armeabi-v7a / Android 5.0 以下）
2. 白名单在 `assets/white.txt`（格式：`包名,Activity名`）
3. 悬浮功能开关在 `license.bin`（256 字节授权令牌）
4. 用 `build.bat <SOC> <Launcher.apk路径>` 打包
5. 验证后刷入

### 8.4 组件替换规则

| 组件 | 是否可替换 | 说明 |
|------|-----------|------|
| Launcher.apk | ✅ 可替换 | 车机桌面，自定义核心 |
| license.bin | ✅ 可选 | 悬浮授权，`--no-license` 可去除 |
| Carlife.apk | ⚠️ 谨慎 | 苹果 CarPlay 组件，一般不动 |
| UsbMedia.apk | ⚠️ 谨慎 | USB 媒体，一般不动 |
| RootExplorer.apk | ⚠️ 谨慎 | 文件管理器 |
| su / 7z / install.sh | ❌ 勿动 | 核心，动了会变砖 |
