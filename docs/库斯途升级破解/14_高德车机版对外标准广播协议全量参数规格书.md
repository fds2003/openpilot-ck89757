## 一、高德车机版广播体系概述

高德地图车机版（Package: `com.autonavi.amapauto`）为第三方车载应用、仪表盘（Cluster）、HUD 抬头显示及智能驾驶领航系统（如 Comma 3 / openpilot）提供了**标准系统级广播通信协议**。

协议采用双向通信架构：
1. **上行数据广播 (`AUTONAVI_STANDARD_BROADCAST_SEND`)**：  
   高德车机版作为广播源，在导航计算、车速变化、车道推荐、摄像头探测、红绿灯状态跃迁时，以 **1~5 Hz** 的频率向 Android 系统广播最新的行车与导航元数据。
2. **下行控制广播 (`AUTONAVI_STANDARD_BROADCAST_RECV`)**：  
   外部应用（如车载中控快捷键、方控按键、智驾系统）向高德发送广播，以实现地图缩放、昼夜模式切换、静音控制、发起算路导航等操作。

## 二、广播机制与安全生命周期规范

### 2.1 接收器注册规范
由于 Android 4.4.2 系统机制限制，接收该广播时**必须采用动态注册（Dynamic RegisterReceiver）**，避免静态 Receiver 频繁唤醒引发的性能抖动：

```kotlin
val filter = IntentFilter("AUTONAVI_STANDARD_BROADCAST_SEND")
context.registerReceiver(amapBroadcastReceiver, filter)
```

### 2.2 数据格式与解包准则
高德广播使用标准 Android `Intent`，内部携带 `Bundle`（`intent.extras`）。由于各版本车机固件历史差异，部分字段可能以 `String`、`Int` 或包装对象形式出现，**解析时必须具备类型自适应与多别名安全降级能力**。

### 3.3 车道级导航与车道推荐拓扑流 (KEY_TYPE = 10019)

在支持车道级导航的路段，高德会通过 `EXTRA_DRIVE_WAY` 吐出一条以竖线 `|` 分隔的车道拓扑字符流（从左侧车道至右侧车道排布）：

```
示例：EXTRA_DRIVE_WAY = "s|s|S|X"
表示前方路段共有 4 条车道：
- 第 1 车道（最左）：s (普通直行车道)
- 第 2 车道：       s (普通直行车道)
- 第 3 车道：       S (官方强烈推荐通行车道，变道目标车道)
- 第 4 车道（最右）：X (前方施工/事故封闭/不可通行车道)
```

#### 车道拓扑字符完全字典

| 字符代码 | 语义说明 | HUD 呈现符号 | 智驾超车状态机处理准则 |
| :---: | :--- | :---: | :--- |
| **`s`** | 普通直行通行车道 | `\|` | 允许自车巡航行驶。 |
| **`S`** | **官方推荐/优选变道车道** | **`^` (高亮)** | **若当前车不在 S 车道，且时距安全，自动触发向该车道变道！** |
| **`X`** | **故障/封闭/禁止变入车道** | **`X` (警示)** | **绝对禁止发起向该车道的任何变道操作！** |
| **`l`** | 普通左转专用车道 | `←` | 仅在路口左转时允许切入。 |
| **`L`** | 推荐左转车道 | `⇐` | 前方左转时的最优车道。 |
| **`r`** | 普通右转专用车道 | `→` | 仅在右转或出匝道时切入。 |
| **`R`** | 推荐右转车道 | `⇒` | 驶出高速出口的最优车道。 |
| **`b`** | 公交专用车道 (Bus Lane) | `B` | 非通行时段禁止变入。 |
| **`t`** | 潮汐可变车道 (Tidal Lane) | `T` | 依据时段信号灯判断。 |

## 四、反向控制广播契约 (AUTONAVI_STANDARD_BROADCAST_RECV)

外部车载应用通过向系统发送 Action 为 `AUTONAVI_STANDARD_BROADCAST_RECV` 的广播，可**反向指挥高德车机版**执行动作：

```kotlin
val intent = Intent("AUTONAVI_STANDARD_BROADCAST_RECV").apply {
    putExtra("KEY_TYPE", 10006) // 算路导航指令
    putExtra("DEST_LAT", 39.9087)
    putExtra("DEST_LON", 116.3975)
    putExtra("DEST_NAME", "北京天安门")
    putExtra("DEV", 0) // 0: 高德坐标 WGS84/GCJ02
}
context.sendBroadcast(intent)
```

| 控制命令代码 (`KEY_TYPE`) | 控制动作 | 所需附加参数 (Extras) |
| :---: | :--- | :--- |
| **`10002`** | 退出导航 / 停止播报 | 无附加参数 |
| **`10003`** | 地图放大一档 (Zoom In) | 无附加参数 |
| **`10004`** | 地图缩小一档 (Zoom Out) | 无附加参数 |

## 六、工程落地最佳实践与 Dalvik 低内存保障

1. **避免频繁创建临时字符串**：  
   `EXTRA_DRIVE_WAY` 吐出的车道拓扑流每秒可能达到 2~5 次。在 `LaneWayParser` 中，严禁使用 `split("|")` 生成多个 String 数组对象，应通过字符指针切片遍历，**彻底消除 Dalvik GC 堆内存抖动**；
2. **防重入与状态记忆机制**：  
   在信号灯倒计时处理中，仅当 `trafficLightStatus` 发生由红变绿（$1 \rightarrow 2$）跳变时才播放绿灯音效，避免倒计时过程中重复发声；
3. **安全限速保护算法**：  
   当 `LIMITED_SPEED` 为 `0` 时，自动采用用户在通用参数中预设的基线限速，防止在未识别道路上限速骤降导致急刹。
