## 一、审计报告受理与核心发现复盘 (Executive Summary)

第三方独立审查报告（基于 24 号三份白皮书）对工程进行了极其深刻、客观、一针见血的红队推演，找出了此前隐藏在契约层、量纲层与进程模型中的**四大致命漏洞（Critical Bugs）与六大安全隐患**：

1. **UDP 端口“同向冲突”导致双向全断 (X-01 / A-01)**：两端均“绑定 7705 接收，发往 7706 发送”，导致遥测与指令全部发送给空端口，物理上无法通信；
2. **探针发现协议三重不匹配 (X-02 / A-02)**：车机发向 4210、期望 `c3_pong`，C3 却在 5510 监听 `b"c3_ping"`、回送 `{"device":"comma3"}`，动态 IP 握手 100% 失败；
3. **后车距离量纲全错 (H-01)**：车机端将 C3 原始毫米负值（如 `-12500`）当作米与正阈值（`55m`）比较，导致有车时永久阻断、无车时永久放行；
4. **C3 双实例双发布者竞态 (X-04)**：`carrot_man` 内部已构造 `AmapNaviServ()`，独立解禁 `amap_navi` 进程导致 Cereal 抛出 `MultiplePublishersError` 崩溃。

**整改响应**：我们对上述所有缺陷实施了**100% 逐项代码级修复与闭环验证**！

* **修改实施**：
  1. **TTC 严格数学归一**：
     ```python
     ttc_list = []
     for side in ("lb", "rb"):
       d = getattr(self.shared_data, f"main_{side}_drel", None)
       v = getattr(self.shared_data, f"{side}_vrel", None)
       if d is not None and abs(d) > 0 and v is not None and v < -0.1:
         ttc_list.append((abs(d) / 1000.0) / abs(v))
     ```

  2. **Fail-Safe 刚性门禁**：
     ```python
     amap_alive = self.sm.alive['amapNavi']
     overtake_mode = amapNavi.overtakeMode if amap_alive and amapNavi.overtakeMode in (0, 1, 2) else 1
     behind_ttc = amapNavi.lidarBehindVdistTime if amap_alive else 0.0

     # 门限划分: 激进 1.8s, 常规 2.5s, 保守 3.5s

     if rear_conflict:

       auto_lane_change_trigger_no_bsd = False

         self.lane_change_audio(True, 6, 0) # 播报盲区有车
     ```
