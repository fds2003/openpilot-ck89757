## 四、硬件规格口径冲突（最高优先级阻塞项）

| 项 | 21 号指南 | 22 号总纲 | docs/custin/VEHICLE_DYNAMICS.md（70ba3d8 提交） |
| :--- | :--- | :--- | :--- |
| 物理 RAM | 2.0 GB，MemTotal 2,059,512 kB | 1 GB LPDDR2/3 | 2.0 GB，MemTotal 2,059,512 kB |
| 可用/空闲 | MemFree 约 150 MB | 系统可用 350~400 MB | 未写 |
| 伴侣应用常驻 | 15.5 MB（占 2GB 的 0.7%） | 3.5 MB，峰值 35~55 MB | 未写 |
| 安全红线 | 不挤压 150MB MemFree | 留 140MB 缓冲带、超 50MB 触发 LMK | 未写 |

影响：

1. 22 号整套"R 挡倒车影像安全堤坝"论证建立在 350MB 可用内存上（209 + 250 = 459 > 350 触发 LMK）；若 21 号的 2.0GB / 150MB 空闲属实，该推导的前提与阈值全部不成立。
2. 25 / 28 号交付报告的 PSS 15.2 / 15.5 MB 与 21 号一致，但与 22 号的"常驻 3.5 MB"口径不一致；三套数字不能同时为真。
3. 刚提交的 70ba3d8（update vehicle hardware specs to 2.0GB RAM and HSAE D531MC）把仓库内规格改成 2.0GB，但 22 / 23 / 25 / 28 号文档仍按 1GB 体系撰写，仓库内文档自身已分裂。

结论（已于 2026-11-03 裁决，见 32_RAM口径统一裁决）：以 2026-10-24 实测报告 §1.3 的 MemTotal 2,059,512 kB ≈ 2.0 GB 为唯一权威口径；"1GB / 可用 350~400MB"为错误前提，22 号总纲与 23 号提示词已按此修订，旧口径的"140MB 缓冲带 / 35MB 警戒线 / 209+250>350 触发 LMK"推导全部撤回。M-34 已在 30 号主索引表中标为已闭环；待补的四项实机证据列于 32 号裁决第六节。
