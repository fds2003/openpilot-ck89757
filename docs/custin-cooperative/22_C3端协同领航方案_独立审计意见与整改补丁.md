## 1. 六大维度独立意见（精炼版）

### 维度 1 · 网络拓扑与通信契约
- 端口矩阵 `车机 listen 7706/5510` + `C3 listen 7705/5510` + `C3→7706` **无冲突、双向闭环成立**。修复白皮书 1.2 的 7705/7706 错配是**正确动作**，保留。
- ⚠ **F-05**：`self.shared_data.app_ip` 是单一全局变量，5510 探针**逐帧覆盖**。车载网内若同时有车机 A（活跃）与误入热点 B（发 `c3_ping`），`app_ip` 会被 B 抢占，20Hz 遥测改投 B、A 断联。
- ⚠ **F-04（安全）**：`amap_navi.py:818` `subprocess.run(json_obj['echo_cmd'], shell=True)` 允许 7705 客户端在 C3 上执行**任意 shell 命令**；且 7705 监听**无源 IP 白名单**，属远端命令执行面。

### 维度 2 · 多线程与进程生命周期
- 新增 `_discovery_responder_thread`、`_headunit_cmd_recv_thread` 均为**独立守护线程 + 独立 socket 阻塞 `recvfrom`**，**不在 `controlsd` 100Hz 主循环内**，不会直接阻塞控制环。✅
- ⚠ 7705 泛洪时 Python GIL 会**间接抢占** `controlsd` 调度时隙（E-4）；`overtake_mode/behind_ttc/app_ip` 为无锁裸赋值（CPython 整字写原子，语义上建议纳入 `lock`）。
- ⚠ **F-08**：`process_config.py:144` 将 `amap_navi` 置为 `always_run`，使其在 **Offroad 下电**时仍常驻，与白皮书"节能合规"描述不完全一致（功耗可接受但需显式披露）。

### 维度 3 · TTC 数学严密性
- ⚠ **F-01（最重）**：`behind_ttc` 缺省 `99.0`（`amap_navi.py:295`），落入 `desire_helper.py:932` 的 `0.0 < behind_ttc < 2.5` **之外** → `rear_conflict=False` → **门禁放行**。雷达掉线/后车未跟踪/静止即 fail-open。与白皮书 5.1"断网绝不失控"矛盾。
- ⚠ **F-02**：`main_lb_drel` 单位 **mm**、`lb_vrel` 单位 **m/s**（`RadarSpeedEstimator`：0.5s 滑窗 + 4m/s² 限幅），公式 `(drel/1000)/abs(vrel)` 数值成立但**高度依赖单位不变式且无断言**；后车静止/丢失时 `lb_vrel` **冻结在旧值**，TTC 长期误判。
- 三级门限 1.8/2.5/3.5s（120km/h ≈ 51/69/117m）：常规/保守**符合工程常识**；激进 1.8s 偏激但属用户自选项——**前提是 F-01 修成 fail-safe**。

### 维度 4 · 功能安全与容灾
- ✅ **驾驶员熔断**（`desire_helper.py:1336-1348`）**真实存在且无条件**：`steering_pressed` 命中即置 `LaneChangeState.off`。人类控制权优先级正确，是**本方案最强的一层门禁**。
- ⚠ **精度提示**：源码熔断条件是**"反向"扭矩**（左变道时打右扭矩 / 右变道时打左扭矩），白皮书 3.4 写的是">1.2Nm 任意方向"——**措辞需对齐**（见 F-10）。
- ⚠ **E-1 推演**：后车多为**车侧后方**目标，毫米波 `leadLeft/leadRight` 覆盖**侧前方**，后车急进可能**不在视锥内** → 唯一后车门禁就是这条 fail-open 的 TTC 通道，"后方来车极速逼近仍可盲切"未真正封死。

### 维度 5 · Cap'n Proto 兼容性
- ✅ **通过**（F-09）：`custom.capnp:74-75` 在 `AmapNavi`（标识 `@0xaedffd8f31e7b55d` 不变）**尾插** `@15 overtakeMode`、`@16 lidarBehindVdistTime`，符合 Cap'n Proto 尾插规范；旧日志回放可反序列化（缺省字段=0），消费端 `getattr` 兜底防崩。
- ⚠ **E-3（必须知晓）**：capnp 对"属性存在但未写入"的缺省是 **0 / 0.0，不是 Python `getattr` 的 1 / 99.0**。升级后**未重编 capnp** 的构建会静默得到 `overtakeMode=0`（=激进 1.8s）+ `lidarBehindVdistTime=0.0`（TTC 恒 0 → 门禁放行）。**部署必须全量重编 capnp**。

### 维度 6 · 代码质量与边界
- ⚠ **F-03**：`amap_navi.py:994` `int(json_obj.get("param",1))` 无类型/异常防御，畸形包 `ValueError` 会连带跳过后面的 `_update_control/_update_sensors`；且 `overtake_mode` **无超时复位**，误设激进模式后 7705 断链仍持续生效。
- ⚠ **F-06**：`desire_helper.py:936` `self.frame % int(2.0/DT_MDL)` 取整使播报周期与名义 2s 偏差，且"盲区有车"每 2s 一次易致听觉疲劳。

## 2. 最小整改 Patch（可直接落地，含回归风险）

> 原则：**保守优先**——宁可错过一次超车，不在后车急进时盲切。以下改动均不触碰 CAN/`steering` 物理层，回归风险低。

### P0-1 `desire_helper.py` 920-940 —— 后车门禁 fail-open → fail-safe
```python
      # 读取高德车机协同超车模式与后方激光雷达时距 (TTC)
      overtake_mode = getattr(amapNavi, 'overtakeMode', 1)
      behind_ttc    = getattr(amapNavi, 'lidarBehindVdistTime', 99.0)
      ttc_valid     = getattr(amapNavi, 'lidarTtcValid', 1)   # ← 新增 capnp 字段（见 P0-2）
      if overtake_mode == 0:   ttc_threshold = 1.8
      elif overtake_mode == 2: ttc_threshold = 3.5
      else:                    ttc_threshold = 2.5

      # fail-safe: 信号缺失/老化(ttc_valid==0) 视为"后车风险未知" → 阻断
      rear_conflict = (not ttc_valid) or (0.0 < behind_ttc < ttc_threshold)
      if rear_conflict:
        auto_lane_change_trigger = False
        auto_lane_change_trigger_no_bsd = False
        # 每 2s 播报一次（F-06: 用独立 timer，勿用 frame 取整）
        if self.lane_change_audio_delay <= 0:
          self.lane_change_audio(True, 6, 0)   # 盲区/后车
          self.lane_change_audio_delay = 2.0
      else:
        auto_lane_change_trigger = lane_change_available and not side_object_detected
        auto_lane_change_trigger_no_bsd = lane_change_available
```

### P0-2 `custom.capnp` —— 追加"新鲜度"位（尾插，继续保持兼容）

## 4. 实车落地 5 条注意事项

1. **先修 P0 再联调**：F-01/F-02/F-03/F-04 为必改项，E-1/E-3 复测通过方可上车。
2. **capnp 全量重编 + 旧日志回归**：两侧（C3 与回放工具）必须同版本，杜绝 E-3 的"缺省 0=激进"静默切换。
3. **7705 加源 IP 白名单**，冻结 `echo_cmd` 的 `subprocess(shell=True)`，消除远端 shell 通道。
4. **联调顺序**：Wireshark 抓 5510/7705/7706 三向 → 确认 5510 握手→`app_ip` 锁定→7706 单播投递 → 单验 7705 `OVERTAKE`→`overtake_mode` 生效 → 封闭场地**有后车**验证 TTC 阻断 → **刻意断雷达/断网**复现 E-1 确认 fail-safe。
5. **建统一心跳老化表**：`overtake_mode`、`behind_ttc`、`app_ip` 均带时间戳 + 超时复位，超时按最保守默认——这是把"四重门禁"升级为真·刚性的总抓手。

> **专家寄语**：`steering_pressed` 熔断与端口错配修复是扎实的安全资产，方向正确。但当前版本把**最关键的后车威胁门禁做成了 fail-open**，与文档"ASIL-D 任何一重不通过立即封锁"存在事实落差。请先封堵 F-01/F-03/F-04 三项 Major，再进实车——**宁可保守错过一次超车，也不要在后车急进时盲切。**
