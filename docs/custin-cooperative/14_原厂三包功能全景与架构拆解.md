| 是否写仪表 | ✅ 唯一写入者 | ❌ | ❌ |

三个包不是一套代码的三个模块，而是三条独立产品线：

```
DuerOS（语音/车控）
   ├─ 语音控制百度 ADAS（NaviControllerService）
   ├─ 语音控制高德（AUTONAVI_STANDARD_BROADCAST_RECV）
   └─ 读取 ADAS 定位广播（NAVI_GPS_CHANGED）

百度地图车机版（独立 UI）
   └─ OpenControl 字符串 RPC（不写仪表）

BaiduMapAutoADAS（独立导航 + 车机深度集成）
   └─ HSAE Binder：仪表、昼夜、电源、音量、蓝牙、BCM、空调/隧道
```

### 1.1 最值得注意的发现

1. **ADAS 是唯一的仪表写入者**，而且是 `android.uid.system`；
   Reborn 作为普通应用能否写仪表仍需实车验证。
2. **ADAS 还有第二条仪表通道**：MnSoft 原生库经 `INavigation` transact 14
   下发 ADAS/电子地平线载荷；此外 `RemoteRenderService` 可把地图渲染到
   `su2_ss`（分屏）和 `su2_svm`（全景影像）Surface。
3. **ADAS 与车机集成很深**：昼夜主题、Micom 电源、导航音量 ducking、
   蓝牙电话、BCM 车身信号、隧道空调联动。
4. **ADAS 的业务面远不止导航**：SOS、组队、停车、违章、收藏、离线/U 盘更新、
   手机发送到车、微信 IoT、BlueLink 远程导航。
5. **百度地图车机版完全不碰 HSAE**，但提供 `OpenControl` 字符串 RPC，
   还有轻导航、桌面小组件、WiFi 传输。
6. **DuerOS 同时支持百度和高德两套导航控制**：百度走 Binder JSON-RPC，
   高德走 `AUTONAVI_STANDARD_BROADCAST_RECV`；默认导航 App 是持久化设置。
7. **DuerOS 是完整的语音车控助手**：车窗、天窗、空调、除霜、座椅加热/通风、
   座椅位置、尾门，能力按 HSAE 车辆配置动态裁剪。
8. **DuerOS 还暴露第三方 SDK**：`CoDriverService` 向其他 App 提供 19 个 tool
   （音乐、电话、TTS、系统、相机、媒体、ASR、蓝牙、硬按键、电台、录音、
   配置、地图、微信、车辆信息、我的声音、对话、智能、智能家居）。
9. 三个包都是**库斯途（KU）定制**：ADAS platform 硬编码 `ku`，
   DuerOS 渠道为 `hyundai_ku`。

### 2.6 ADAS 电子地平线（第二条仪表通道）

- Java 侧：`dataenginesdk.AdasMapManager`（JNI → `libdata_engine.so`）提供
  曲率、车道线、文本等绘制数据。
- 原生侧：`libMapAutoToADAS.so`（MnSoft）内的 `AdasManager` 生成
  position/segment/profile/curve/range/traffic/tunnel 等消息。
- 出口：`MapAutoToNaviService.sendClusterADASParser(byte[], type)`
  → `INavigation` transact 14；`type == 407` 特判为相机提醒设置。
- 该通道与 TBT 独立，Reborn 本期不使用（文档 11 §1.2）。

- `sharedUserId="android.uid.system"`，这是它能直接调用 HSAE 系统服务、

### 3.3 OpenControl（对外控制接口）

- `OpenControlService`：action `com.baidu.baidumaps.opencontrol.ACTION.REQUEST`，
  extras：`package_name`、`version`、`content`、`transaction`；
  结果 action `...ACTION.RESPOND`。
- `OpenControlAIDLService`：需要自定义权限 `com.baidu.map.permission.OPEN_CONTROL`
  （Manifest 未展示 protectionLevel，实际是否为签名级需进一步核对）。
- `content` 是 `{method, params}` JSON，支持约 40 个方法：
  `enterApp/exitApp/enterNav/exitNav/navToLoc/selectNav/switchRoute/
   remainLeftTime/remainLeftDistance/aheadRoadName/nextTurnDistance/
   isNavigating/getNaviDesName/getNaviDesCoordinate/mapRoutePlanning/
   switchTraffic/switchTo2D/switchLightNightMode/zoomIn/zoomOut ...`
- 定位：只控制百度地图 UI/导航，不写仪表。

### 4.5 导航调度（已核实，重要）

DuerOS 不是只控百度，它有两套导航适配：

| 默认导航 App | 控制方式 | 关键类 |
|---|---|---|
| 百度 ADAS (`d.Baidu`) | 绑定 `com.baidu.NaviControllerService`，JSON-RPC `fun_navi_*` | `NaviCmdController`、`NaviControllerManager` |
| 高德 (`d.Amap` / `d.Amap_Lite`) | 发 `AUTONAVI_STANDARD_BROADCAST_RECV` | `AmapIntentManager`、`AmapKeyType` |

- 默认值：`NaviPreferences` 中 `key_default_navi_app`，缺省 `Baidu`。
- 高德控制 key（`AmapKeyType`）：
  `10009` 开始导航、`10010` 退出导航、`10027` 缩放/路况/视角、
  `10034` 打开高德、`10021` 关闭、`10048` 昼夜、`10005` 路线策略、
  `10006` 全览、`10045` 查家/公司、`10058` 设家/公司、`12404` 查询状态。
- 高德反馈监听：`AUTONAVI_STANDARD_BROADCAST_SEND`
  - `KEY_TYPE=10019`：前台/后台/退出、路线规划成功、开始/结束导航、心跳
  - `KEY_TYPE=10046`：家/公司地址查询结果、心跳
- 心跳：5s 查询一次，8s 收不到即判定高德不在线。

> 这意味着车机上已经存在“语音控制高德”的完整通道；
> Reborn 只需要继续监听 `AUTONAVI_STANDARD_BROADCAST_SEND`，不会与 DuerOS 冲突。

## 5. 三包之间的 IPC 全景

### 5.1 DuerOS → ADAS（语音控制导航）

```
DuerOS.NaviCmdController
  → NaviControllerManager.sendRequest(func, params)
  → bind com.baidu.NaviControllerService
  → ADAS.NaviControllerService (Binder)
  → ADAS.DuerOSReceiver (common/h/a/a.java)
  → 内部广播 com.baidu.mapauto.*
  → ADAS.DuerOSResponser (common/h/a/b.java)
  → sendResponse(errorNo, requestId, func, result)
```

`func` 词汇：`fun_navi_app_control`、`fun_navi_navi_state`、
`fun_navi_route_plan`、`fun_navi_start_task`、`fun_navi_map_control`、
`fun_navi_mute`、`fun_navi_limit_speed`、`fun_navi_query_traffic`、
`fun_navi_poi_search`、`fun_navi_via_search`、`fun_navi_syn_address`、
`fun_search_along_*` 等。

**握手细节（已核实）**：

```
DuerOS: bindService(Intent("com.baidu.NaviControllerService")
                     .setPackage("com.baidu.mapauto")
                     .putExtra("from", "remoter"))
ADAS:   NaviControllerService.onBind() → 返回远程 Binder（from=remoter）
DuerOS: IServiceBinder.register(0x10000, ICallback)
ADAS:   返回 0x10000（版本 1.0）；主版本不一致 → 事件 5（版本不匹配）
```

- AIDL 描述符：`com.baidu.navicontroller.aidl.IServiceBinder`、
  `com.baidu.navicontroller.aidl.ICallback`。
- 消息元组：`(type, errorNo, requestId, func, params)`；
  `type`：1=请求、2=响应、3=通知。
- 断线重连：10s 心跳/`linkToDeath`，失败自动重绑。

**拉起 Activity（已核实）**：

```
Intent(action="com.baidu.mapauto.action.START",
       data=Uri.parse("codriver://"))
  .setFlags(FLAG_ACTIVITY_NEW_TASK)
  .putExtra("start_navi_cmd", true)   // 需要直接开始导航时
```

ADAS 的 `MapAutoActivity` 在 Manifest 中注册了
`action=com.baidu.mapauto.action.START` + `scheme=codriver` 的 intent-filter。

### 5.7 包间通道总表

| 源 → 目标 | 方式 | 标识 | 载荷 | 直接 |
|---|---|---|---|---|
| DuerOS → ADAS | 绑定 Service（Binder） | `com.baidu.NaviControllerService` + package `com.baidu.mapauto` + `from=remoter` | `(type,errorNo,requestId,func,params)` JSON | ✅ |
| DuerOS → ADAS | Activity Intent | `com.baidu.mapauto.action.START` + `codriver://` | `start_navi_cmd` | ✅ |
| ADAS → DuerOS | 隐式广播 | `com.baidu.mapauto.action.NAVI_GPS_CHANGED` | 经纬度/高度/航向/剩余距离时间 | ✅ |
| DuerOS → 高德 | 广播 | `AUTONAVI_STANDARD_BROADCAST_RECV` | `KEY_TYPE` | ✅（高德非三包之一） |
| 高德 → DuerOS | 广播 | `AUTONAVI_STANDARD_BROADCAST_SEND` | `KEY_TYPE=10019/10046` | ✅ |
| 百度地图 → 第三方 | Service/Intent | `OpenControl` | `{method,params}` JSON | ✅（未发现另两包使用） |
| 百度地图 ↔ ADAS | — | — | — | ❌ |
| 百度地图 ↔ DuerOS | — | — | — | ❌（仅 SAPI2 账号授权表） |
| ADAS ↔ DuerOS（音频） | HSAE 音频焦点 | `IBINDER_SOURCE` + `com.baidu.che.codriver.tts.AudioFocusManager` | 焦点/ducking | 间接 |
| 三者 ↔ 系统 | HSAE Binder | 见 §5.6 | — | 间接 |

### 5.8 关键结论

1. **有直接数据传递的只有 DuerOS ↔ ADAS**：
   一条 Binder（导航控制）、一条 Activity Intent（拉起/开始导航）、
   一条广播（定位与行程）。
2. **百度地图车机版与另外两个包没有直接 IPC**：
   BaiduMap 的 dex 里没有任何 `com.baidu.mapauto` 引用；
   ADAS 也不引用 `com.baidu.BaiduMap.auto`。
   BaiduMap 里唯一出现的 `com.baidu.che.codriver` 是 SAPI2 的签名授权表
   （`SapiOptions.initialAuthorizedPackages`），用于账号 SSO，不是导航数据。
3. 三者之间**没有共享文件、Socket、ContentProvider** 形式的业务数据通道。
4. DuerOS 与高德是另一条独立链路，不经过 ADAS。
5. 音频层面通过 HSAE 的 source/audio focus 服务间接协调
   （ADAS 的 `SourceConst.BAIDU_VR_FOCUS` 指向 DuerOS 的 `AudioFocusManager`），
   不是包间直连。

## 7. 对 Reborn / 车机改造的启示

1. **ADAS 是仪表主写者**：只要原厂 ADAS 在前台导航，它就会写仪表。
   Reborn 的 `cluster_enable` 开关必须与“百度导航是否在跑”联动，
   否则会出现双写（文档 11 §12、文档 13 §10.4）。
2. **DuerOS 的默认导航 App 是持久化设置**：`prefs_amap/key_default_navi_app`，
   缺省 `Baidu`。如果车机上把默认导航切成高德，语音指令会直接走高德广播；
   Reborn 只监听广播，不受影响，但可以作为“语音控高德”的现成通道参考。
3. **高德控制广播契约已现成**：`AUTONAVI_STANDARD_BROADCAST_RECV` + `AmapKeyType`。
   如果 Reborn 未来要做“语音/按钮控制高德”，可直接复用这套 key，
   不必自己发明协议。
4. **ADAS 的车机集成值得借鉴**：昼夜、电源、音量 ducking、蓝牙电话、
   隧道空调联动。Reborn 若要“像原厂一样”，这些是体验差距的主要来源。
5. **权限门槛**：ADAS 是 system uid；Reborn 是普通应用。
   仪表写入、车辆信号读取都可能受 uid/权限限制，上车前必须先用探针验证。
6. **不要碰的边界**：ADAS 的 ADAS 电子地平线（transact 14）载荷格式不公开，
   且与 C3 的感知链路重复；Reborn 本期不接。
