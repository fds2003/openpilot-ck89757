# 12 仪表投影布局对照与修正参考

> 对照对象：`E:\code\adbridge-cluster`（M1）与 `E:\code\adbridge-custin`（实车版）
> 目的：把“HSAE 仪表到底怎么写”固化成可核对的字段顺序，避免再靠注释猜。
> 关联：`11_仪表移植方案.md`

---

## 1. 结论

- `adbridge-cluster` 是**早期 M1 简化版**：Parcel 布局、数据源、图标映射、交还序列都不完整。
- `adbridge-custin` 是**实车版**：布局与交还已对齐；但限速取的是 `CAMERA_SPEED`，
  图标映射仍需要实车标定。
- 本文以 **custin 的字段顺序为权威参考**，cluster 的偏差逐项列出。

## 2. 两版对照

| 能力 | cluster（311 行） | custin（713 行） |
|---|---|---|
| 导航模式握手 | ❌ 无 | ✅ `tx 3` + `tx 2` |
| TBT 布局 | 简化：`scale=0`、`distToTurn=0` | 完整：km/m + 小数位 |
| 限速布局 | `speed + 9×0` | `6×0 + 1/0/1 + speed` |
| 行程布局 | `unit=0` + km 值 | unit 计算 + 小数 + format/type=1 |
| 目的地旗 | ❌ | ✅ ≤15m 切旗 |
| 交还 | 只 `255 + 空串` | `tx2/3 + 罗盘 8 + 清空` |
| 限速钳制 | ❌ | ✅ 20–150 + 变化率 |
| 图标映射 | 一套（注释） | 另一套（“实测”注释） |

## 3. 数据源对照

| 仪表项 | cluster | custin | 建议 |
|---|---|---|---|
| 路名 | `NEXT_ROAD_NAME` | `NEXT_ROAD_NAME` | **+ `CUR_ROAD_NAME` 回退** |
| 行程 | `ROUTE_REMAIN_DIS/TIME` | 同 | 同 |
| 限速 | `CAMERA_SPEED` | `CAMERA_SPEED` | **`LIMITED_SPEED` 优先，`CAMERA_SPEED` 回退** |
| 红绿灯 | `60073` | `60073` | **60073 + 10001 都接受** |
| 航向 | ❌ | `CAR_DIRECTION` | 本期不做 |
| 结束 | `EXTRA_STATE 9/0` | 同 | + **3s 无广播超时** |

> cluster/custin 都用 `CAMERA_SPEED` 做圆牌，这是“和高德对不上”的一个来源：
> 没有电子眼就没有圆牌，有电子眼时显示的是抓拍限速而不是道路限速。

## 4. 权威布局（custin）

### 4.1 接管 / 交还

接管（首次进入导航，一次）：

```
INavigation 3：writeInt(1) + writeByte(100)      // setDisplayTG(true)
INavigation 2：writeByte 0,0,0,1,1               // navi=1
```

> **原厂对照（2026-11-07）**：`BaiduMapAutoADAS` 从不调用 transact 3 或 2，
> 直接写 transact 1 就能让仪表从罗盘切到箭头（见 `13` §4.4/§10.2）。
> 另外 transact 2 的官方方法名是 `setHuLanguageInfo`，不是“导航模式开关”，
> custin 把它当接管开关的用法语义存疑。
> Reborn 第一版应先只写 1/5/6/46；实车不显示时再补 3/2，并做 A/B 验证。

交还（开关关闭 / 导航结束 / 服务停止）：

```
INavigation 2：writeByte 0,0,0,0,0               // navi=0
INavigation 3：writeInt(0) + writeByte(0)        // setDisplayTG(false)
INavigation 1：displayType=8, sideStreet=15,
               direction=0, distVal=0,
               combinedSideStreet=15, scale=0,
               distToTurn=0                      // 恢复原车罗盘
IVehicle  46：writeByte(6) + writeString("")     // 清空文本行
```

### 4.2 TBT（INavigation 1）

```
writeByte(displayType)
writeInt(15)              // sideStreet
writeByte(0)              // direction
writeInt(distVal)
writeByte(15)             // combinedSideStreet
writeByte(scale)          // 0=米, 1=公里
writeByte(distToTurn)     // 公里一位小数
transact(1, ...)
```

距离算法（与 custin 一致）：

```
>= 100 km : distVal = m/1000,           scale=1, 小数=0
1–100 km  : r=(m+50)/1000,              distVal=r, scale=1, 小数=(r/100)%10
< 1000 m  : distVal = m,                scale=0, 小数=0
```

目的地旗：`distMeters <= 15` 且 ICON 为 1/2 时，`displayType=2`。

### 4.3 限速（INavigation 5）

```
writeByte(0)   // overSpdAlarm
writeByte(0)   // nonSpdTrap
writeByte(0)   // warningZone2
writeByte(0)   // warningZone
writeByte(0)   // warningZone3
writeByte(0)   // curveWarning
writeByte(1)   // spdLimitType（有效）
writeByte(0)   // spdLimitUnit（km/h）
writeByte(1)   // spdInfoType
writeByte(v)   // spdLimit ← 必须最后
```

钳制：`SPD_MIN=20`、`SPD_MAX=150`、`SPD_MAX_DELTA_PER_SEC=20`。

### 4.4 行程（INavigation 6）

```
writeByte(distF)            // 小数
writeByte(unit)             // 0=米, 1=公里
writeByte(min(hours,99))
writeByte(min(minutes,59))
writeByte(0)                // azimuth
writeInt(distI)             // 距离数值
writeByte(1)                // estimTimeFormat
writeByte(1)                // estimTimeType
writeByte(0)                // estPointType
```

距离算法：

```
>= 100 km : distI = m/1000, distF=0, unit=1
1–100 km  : r=(m+50), distI=r/1000, distF=(r/100)%10, unit=1
< 1 km    : distI = m, distF=0, unit=0
```

### 4.5 文本行（IVehicle 46）

```
writeByte(6)
writeString(text)
```

文本格式：

```
[红灯 18s] <路名>
[绿灯 12s] <路名>
[黄灯 3s]  <路名>
<路名>
```

红绿灯状态映射：`1=红, 2=绿, 3=黄, 4=绿`；未知不加前缀。
路名建议截断 24 字符。

## 5. `adbridge-cluster` 的具体偏差

| 项 | cluster 做法 | 后果 | 修正 |
|---|---|---|---|
| TBT 布局（`HsaeClusterClient.java:107`） | `byte icon, int dist, 0,0,0,0,0` | 无 km/m、无小数、无 sideStreet | 按 §4.2 |
| 导航模式握手 | 未发 `tx 3/2` | 部分固件不进入导航显示 | 首次 TBT 前发 |
| 限速布局（`:180`） | `speed + 9×0` | 服务端把 speed 当 `overSpdAlarm`，圆牌不生效 | 按 §4.3 |
| 行程布局（`:141`） | `unit=0` + `distI=km` | 单位与数值矛盾 | 按 §4.4 |
| 交还（`:209`） | 只 `255 + 空串` | 仪表可能停在旧箭头，百度不能及时接管 | 按 §4.1 |
| 限速源 | `CAMERA_SPEED` | 无电子眼无限速；显示抓拍限速 | `LIMITED_SPEED` 优先 |
| 红绿灯条件 | `kt==-1 || kt==60073` | 10001 包内的灯被忽略 | 60073 + 10001 |
| 超时 | 无 | 广播停止后仪表停在旧数据 | 3s 无数据交还 |
| 去重 | 无 | 每帧都写，闪烁/占 Binder | 变化检测 + 节流 |
| 图标映射 | 2=直行… | 与 APK 语义冲突 | 实车标定，见 §6 |

## 6. 图标映射：已由原厂 APK 定案

原厂 `BaiduMapAutoADAS.apk` 的 `NaviClusterManager.convertMapAutoTypeToDisplayType`
把 Baidu 转向枚举直接映射到 HSAE 显示码，枚举名即语义。
完整证据与链路见 `13_原厂三包与仪表投影分析.md`。

**HSAE 显示码语义（权威）**：

| 码 | 语义 |
|---:|---|
| 65 | 直行/居中 |
| 66 | 右前方 |
| 67 | 右转 |
| 68 | 右后方 |
| 69 | 左后方 |
| 70 | 左转 |
| 71 | 左前方 |
| 72 | 掉头 |

**高德广播 `ICON` 的实际编号**（custin 实车标定）与原厂码对齐后：

| Amap ICON | 语义 | HSAE 码 |
|---:|---|---:|
| 2 / 10 / 18 / 19 | 直行、直行通过、顺行、驶入主路 | 65 |
| 3 | 左转 | 70 |
| 4 | 右转 | 67 |
| 5 / 16 | 左前方、靠左 | 71 |
| 6 | 右前方 | 66 |
| 7 | 左后方 | 69 |
| 8 | 右后方 | 68 |
| 9 | 掉头 | 72 |
| 11/12/14/17/20 | 环岛/收费站/靠右/匝道 | 未标定，先 255 |

> **旧文档的两处错误已纠正**：
> 1. `convert_tbt_type` 不是“ICON→语义”表，它把高德 ICON 映射到百度导航 SDK 的
>    机动码（12/13/7/6/142/153），不能拿来当图标语义依据；
> 2. 高德广播 `ICON` 不是常见的 1=直行、2=左转，而是 2=直行、3=左转
>    （整体右移一位），custin 的“实测”表才是对的，cluster 的 M1 表是错的。

未标定项仍按 §5 的流程实车验证，验证前一律 255。

## 7. 频率、去重、超时

| 通道 | 发送条件 | 最小间隔 | 保活 |
|---|---|---|---|
| TBT | 图标或距离变化 | 500ms | 2s |
| 限速 | 值变化 | 1s | — |
| 行程 | 公里/分钟变化 | 10s | 10s |
| 文本行 | 路名/灯态变化 | 1s | 1s（倒计时） |
| 交还 | 开关关 / 导航结束 / 3s 无广播 | — | — |

## 8. 实车核对清单

1. 进入导航：仪表出现箭头、米数、限速、行程、路名。
2. 直行/左转/右转/掉头：箭头方向与高德一致。
3. 1.5km 路口：仪表显示“1.5 km”，不是“1500 m”。
4. 无电子眼路段：限速圆牌应显示道路限速（`LIMITED_SPEED`）。
5. 红绿灯：文本行出现 `[红灯 Ns]` 并逐秒递减。
6. 导航结束：箭头消失、恢复罗盘、文本清空。
7. 开关关闭：百度导航可正常接管。
8. 关闭高德广播 3s：仪表自动交还，不停在旧数据。
