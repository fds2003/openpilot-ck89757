## 一、统一方案核心宗旨：双端职责边界的彻底重构

### 1.1 历史致命原罪：弱端决策与强端执行的危险倒置
在跨工程协同深度分析报告（`库斯途双工程协同分析报告_4db08403.md`）中，红队专家指出了一个触目惊心的系统性架构设计缺陷：
* **原架构设计倒置**：原方案试图把“实线判定、侧后方安全距离净空模型、驾驶员干预判定”等生死攸关的安全仲裁权交给车机端；
* **弱端的本质局限**：车机端是一台搭载 2012 年架构 NXP i.MX6 四核 1.0GHz 芯片、运行 Android 4.4.3 KitKat、基于 Dalvik 虚拟机的车载娱乐主机。车机系统**毫无车载功能安全等级（No ASIL rating）**，且通过一条极其脆弱的消费级 Wi-Fi UDP 局域网与 C3 链接；
* **严重后果**：一旦车机发热降频、Dalvik 发生 GC 停顿、Wi-Fi 丢包或高德广播延迟，车机端决策就会冻结或失效，从而诱发恶性失控。

---

### 1.2 工业级架构重划：“车机提建议、C3全权独立安全仲裁”
本方案确立现代汽车工程标准的**“零信任分权架构（Zero-Trust Asymmetric Architecture）”**：

## 二、整车软硬件全景真相终局裁决

### 2.1 车机物理 RAM 2.0GB 唯一口径与真实调度模型
依据《北京现代库斯途车机系统全景深度检测与分析报告_20261024.md》底层 `/proc/meminfo` 的原始实测数据：
* **唯一权威真相**：**车机主板物理运行内存为整整 2.0 GB (`MemTotal: 2,059,512 kB`)**；历史文档中“1GB / 扣除显存后可用 350~400MB”纯属早期口径偏差，自本方案起彻底废除；
* **真实调度模型**：
- 系统常驻运行航盛电子固化的数十款原厂车载进程；
- 高德地图车机版（实车与测试手机统一安装版：`高德地图车机版8.5.0.600050悬浮(靓华修改).apk`，`com.autonavi.amapauto` v8.5.0.600050）在导航时自身常驻占用约 **`209 MB`**；
- 采样瞬间的自由物理页（`MemFree`）保持在 **约 150 MB 左右**，可动态回收缓存 `Cached` 约 900MB。
### 2.2 伴侣应用常驻 PSS 15.5MB 的真正价值：保卫倒车影像生命线
* **安全风险机理**：库斯途车身长达 4,950 mm，车后盲区极大。当驾驶员挂入倒车挡（R 挡）时，原厂倒车影像服务 **`com.hsae.d531mc.vm` (`ViewMonitor.apk`)** 必须在 **0.5 秒内**抢占底层显存并显示画面；
* **为什么内存依然要极度节制？**
  虽然车机有 2.0GB 总内存，但 Android 4.4 Dalvik 虚拟机对单个应用的 Java 堆配额极度紧缩。原版应用狂吞 250MB 导致内存严重碎片化，迫使系统 LMK 频繁杀后台，导致挂入 R 挡时倒车影像卡死 2~3 秒甚至黑屏；
* **重构价值**：`AmapNavi-Reborn` 的 PSS 实测仅为 **`15.5 MB`**（仅占 2GB 内存的 **0.7%**），完全不挤压 150MB 空闲自由内存，**确保倒车影像毫秒级极速秒开，固若金汤**。

### 2.3 现代库斯途 2.0T 顶配旗舰版专属物理机械 DNA
* **车型代号**：`HYUNDAI_CUSTIN_1ST_GEN`（配 `CarHarness.hyundai_k` 前视线束）；
* **发动机与扭矩**：Smartstream 2.0T 涡轮增压发动机（**236 马力 / 353 N·m**，1500rpm 爆发峰值扭矩）；
* **传动机构**：现代自研 8AT 变速箱，**按键式电子换挡 (Shift-by-Wire, SBW)**；
* **车身物理几何**：整备质量 **`1,754 kg`**（满载达 2,300 kg），轴距 **`3,055 mm`**（超长轴距），车高 **`1,734 mm`**（高重心），后扭力梁非独立悬挂，转向比 17.0。

### 2.4 Comma 3 (tici) 硬件规格与夏季暴晒待机温控
* **计算核心**：高通 SDA845（8核 Kryo 385，Adreno 630 GPU，4GB LPDDR4x，64GB UFS 2.1 高速闪存）；
* **底层系统**：AGNOS Linux aarch64（基于 Ubuntu 20.04，搭载 `4.9.103` PREEMPT_RT 实时内核）；
* **总线接口**：集成 Comma Panda（硬件类型 `HW_TYPE_DOS (\x06, STM32F413)`，直连 500kbps 现代 C-CAN）；
* **温控机制**：库斯途平缓大风挡中控台夏季暴晒可达 70℃。车辆熄火待机（Offroad）时，**强制关断高通 845 的 4 个 A75 大核，整机待机功耗骤降至 1.65W，核心稳定在 39℃ 绿区**。

## 三、P0 阻断级缺陷与安全隐患根除方案

### 3.1 消除力矩重复定义导致的启动 RuntimeError (override vs substitute)
* **缺陷根因**：
  `opendbc_repo/opendbc/car/torque_data/override.toml:77` 与 `substitute.toml:43` 同时定义了 `"HYUNDAI_CUSTIN_1ST_GEN"`，触发 `interfaces.py:79-80` 的重复定义断言，导致 openpilot 启动加载力矩时抛出 `RuntimeError` 崩溃；
* **根除方案**：
  **彻底删除 `override.toml:77` 中的库斯途条目，独占保留 `substitute.toml:43` 的帕里斯帝 NNFF 模型映射**。单一数据源彻底根除启动崩溃，确保系统 100% 平稳开机！

---

### 3.2 彻底解耦后车 TTC 时距：空车道放行与失联 Fail-Safe
* **缺陷根因 (F-32-01)**：
  此前代码在后方无逼近车辆（空车道）时，将 `ttc` 误赋值为 `0.0`，导致消费端判定 `behind_ttc <= 0.0` 恒成立，造成“空车道所有变道被永久锁死”的致命故障；
* **根除方案**：
  实施严格的**三态解耦算法**：
  $$\text{TTC} = \begin{cases} 
  99.0\text{ s}, & \text{传感器在线，且后方净空无逼近车辆 (安全放行，允许变道)} \\
  \min(\text{TTC}_{approaching}), & \text{检测到后车以相对速度急追 (若 } < \text{门限则刚性阻断)} \\
  0.0\text{ s}, & \text{传感器离线/超时/无数据 (Fail-Safe 刚性阻断)}
  \end{cases}$$
  消费端判定公式冻结为：`rear_conflict = (behind_ttc <= 0.0) or (0.0 < behind_ttc < ttc_threshold)`。彻底兼顾了空车道变道的平稳可用性与极端断线下的绝对功能安全。

---

### 3.3 彻底封闭远程未授权命令注入面 (封死 echo_cmd RCE 与界面开关防御设计)
* **缺陷根因**：
  此前代码中残留有通过 UDP 4213 或 ZMQ 7710 接收 `echo_cmd` 并直接调用 `subprocess.run(shell=True)` 的调试后门，局域网内任何设备均可借此在 C3 上远程执行 root 命令；且原有测试仅在测试文件内用 mock 函数验证，未在生产代码中真正建立防御网关；
* **车规级四重纵深防御方案 (界面开关 + 行车硬锁死 + IP白名单)**：
  1. **UI 界面显式设置安全硬开关 (Default Off)**：
     在 Comma 3 设备设置界面（`CarrotPanel`）中专门增设【允许远程命令调试 (Remote Debug Echo Cmd)】切换开关，绑定持久化参数 `CarrotEchoCmdEnable`，**出厂及生产环境默认永久关闭 (`0`)**；
  2. **高危操作防误触安全弹窗确认**：
     当车主在屏幕上点击开启该开关时，UI 必须弹出红色阻断式二次确认弹窗：*“【高危调试警告】开启此功能将允许局域网发送系统级 Shell 命令，仅供专业人员在私有安全网络离线排错，行车中将强制锁死。确认开启？”*，避免车主无意开启；
  3. **行车物理硬锁死机制 (Onroad Hard Lockout - 423)**：
     即便车主在界面上开启了开关（`CarrotEchoCmdEnable = 1`），只要底层检测到车辆进入行车/点火就绪状态（`IsOnroad == True`），安全网关**无条件触发硬锁死拦截**，直接返回 `{"exitStatus": 423, "error": "echo_cmd is locked during onroad driving for safety"}`，杜绝在行驶途中受任何网络指令干扰转向或系统稳定性；
  4. **仅限驻车/离线调试执行与审计日志**：
     当且仅当【界面开关开启 (`=1`)】且【车辆严格处于驻车/熄火离线状态 (`IsOnroad == False`)】双重前置条件满足时，才允许执行调试指令，并强制向系统安全日志记录调用来源 IP 与执行命令；
  5. **强源 IP 白名单校验 (Source IP Whitelist)**：
     在 UDP/ZMQ 接收网关层，强校验来源 IP 必须与探针握手认证的车机 IP（`app_ip`）一致，匿名或第三方网络请求直接在 socket 缓冲区丢弃。

---

### 3.4 车机高德广播按 KEY_TYPE 精准过滤与 2.0s 老化看门狗
* **缺陷根因**：
  此前车机端 `AmapBroadcastDecoder.kt` 收到高德广播未区分 `KEY_TYPE`，导致 10019 电子眼广播覆盖 10001 导航广播，造成导航状态瞬间被冲掉；且 `NaviState` 缺乏超时机制；
* **根除方案**：
  1. 严格按照官方规格字典分流：`KEY_TYPE == 10001` 解码车速、限速、路口距离；`KEY_TYPE == 10019` 解码车道拓扑字符流与信号灯；
  2. 建立 2.0 秒老化看门狗：超过 2.0 秒未收到高德广播，自动置 `navValid = false`，杜绝使用陈旧失效地图数据控车。

---

### 3.5 废除“超时即成功”假象：变道超时严格结算为失败撤销
* **缺陷根因**：
  此前车机端 `OvertakeStateMachine.kt` 在变道执行超时（4.5秒）未收到底层完成反馈时，代码注释写着“按完成结算”，播放成功音并进入冷却，导致卡住或失败的变道被误报为成功；
* **根除方案**：
  超时期未收到 `atc_state == 3` 完成反馈时，**严格执行撤销指令（下发 CANCEL）、播放取消警报音并锁定长冷却**，彻底消除虚假成功。

### 5.2 探针动态 IP 学习与底层物理源地址防自指
* **握手流程**：
  1. 车机启动向 `255.255.255.255:4210` 发送探针：`{"cmd":"discover","port":5510}` 及 `c3_ping`；
  2. C3 端 `_discovery_responder_thread` 监听 4210，通过本地套接字路由探测（`s_tmp.connect((ip, 80))`）提取 C3 自身真实内网 IP，并原路回送：
     ```json
     {
       "resp": "c3_pong",
       "device": "comma3",
       "status": "ready",
       "device_id": "c3",
       "auth": true,
       "ip": "192.168.3.243",
       "version": "openpilot-cp-custo"
     }
     ```
  3. 车机端底层优先采信底层 UDP 物理源地址 `packet.address.hostAddress`，过滤 `127.0.0.1`，双重保险彻底消灭“车机把指令发给自身”的静默故障。

### 5.3 81项遥测下行与自适应正米制距离归一
* **C3 端发送规范**：
  在 `amap_navi.py:1810` 中，`lb_drel` 与 `rb_drel` 统一换算为**正米制浮点数（如 42.0）**；
* **车机端接收规范**：
  在 `CarrotTelemetryParser.kt` 中引入自适应归一算法（阈值取 200m）：
  ```kotlin
  private fun parseDistanceMeter(rawVal: Float): Float {
      if (rawVal <= -999000.0f || rawVal == 0.0f) return 999.0f
      val absVal = Math.abs(rawVal)
      return if (absVal > 200.0f) absVal / 1000.0f else absVal
  }
  ```
  彻底消灭双重除以 1000 导致的 0.042m 贴身误判。

### 5.4 上行控制指令规格：单调自增序号与 10s 闲置复位
```json
{
  "cmd": "OVERTAKE",
  "arg": "LEFT",
  "direction": "LEFT",
  "param": 1,
  "seq": 1024,
  "index": 1024,
  "v_cruise": 120,
  "blinker": 1,
  "timestamp": 1730592000000
}
```
* **单调门控**：C3 仅在 `seq > cmd_index` 时放行指令；
* **重启自愈**：连续 10 秒无新指令自动重置 `cmd_index = -1`，车机 App 重启后序号自 1 起步秒级无缝接纳；
* **撤销闭环**：车机发送 `CANCEL_LANE_CHANGE`，C3 转换为 `"CANCEL"`，`desire_helper.py` 在 **50ms 内立即注销变道状态机，清空计数，回正车身并播报“领航已退出”**。
