# 13 原厂三包与仪表投影链路分析

> 分析对象：`DuerOS_Auto.apk`、`百度地图车机版3.1.0.apk`、`BaiduMapAutoADAS.apk`
> 方法：jadx 反编译 + HSAE 官方 SDK 常量 + 原生库符号检查 + Manifest 核对
> 用途：给 Reborn 仪表移植提供“原厂真值”，并修正 `11`/`12` 中关于图标与接管握手的描述
> 基线：2026-11-07

---

## 1. 结论

1. **三个包里只有 `com.baidu.mapauto`（BaiduMapAutoADAS）会写仪表**。
   `DuerOS_Auto` 与 `百度地图车机版` 的 Java 代码、原生库里都没有任何
   `cluTbtControl` / `IBINDER_NAVIGATION` / `sendInfoToCluster` 调用。
2. 原厂写仪表的完整链路是：

   ```
   Baidu 导航回调
     → ClusterInfoHandler            (common/b/b.java)
     → IClusterInfoHandler 实现       (common/integration/c/d.java, SU2HUDController)
     → MapAutoToNaviService          (hsae/autosdk/tbt/MapAutoToNaviService.java)
     → NaviClusterManager            (hsae/autosdk/tbt/NaviClusterManager.java)
     → NaviClusterUpdater            (hsae/autosdk/tbt/NaviClusterUpdater.java)
     → INavigation.transact(1/6) + IVehicle.transact(46)
   ```

3. 原厂**只写 4 类内容**：TBT 箭头与距离、行程剩余、目的地文本、罗盘/目的地旗/状态码（有限）。
   **不写限速**（`updateAssistInfo` 是空实现，只打日志），**不做接管握手**
   （从不调用 `setDisplayTG` / `setHuLanguageInfo`），**不写电子地平线**
   （`updateAdasMap*` 在本包内无调用方）。
   隧道信息也不进仪表：`updateTunnelInfo` 在 HSAE 适配层是空实现，
   `SU2HUDController` 走的是 `AirProxy`/`VoiceProxy`（空调隧道模式、语音）。
4. `displayType` 的语义已由 Baidu 转向枚举名与 HSAE 码交叉确认：
   **65 直行、66 右前、67 右转、68 右后、69 左后、70 左转、71 左前、72 掉头**。
   `adbridge-custin` 的“实测”表与之一致；`adbridge-cluster` 的 M1 表是错的。
5. 原厂 ADAS 带 `android:sharedUserId="android.uid.system"`，以 system uid 调 HSAE Binder。
   Reborn 作为普通应用能否写仪表，必须实车确认（见 §10.5）。

## 3. 原厂仪表投影链路

### 3.1 数据来源

`ClusterInfoHandler`（`com/baidu/mapauto/common/b/b.java`）向百度导航 SDK 注册监听：

| 回调 | 事件号 | 转发给 `IClusterInfoHandler` | 用途 |
|---|---:|---|---|
| `onTurnInfoUpdated` | 0 | `a(turnKind, nextRoadName, remainDistance)` | TBT 箭头 + 距离 |
| `onSafetyInfoUpdated` | 12 | `a(visible, type, remainDistance)` | 安全提醒（最终进 `updateAssistInfo`，空实现，实际丢弃） |
| `onRemainInfoUpdated` | 6 | `a(destName, remainTime, remainDistance)` | 行程剩余 |
| `onTunnelInfoUpdated` | 9 | `a(distance, status)` | 隧道（转 AirProxy/VoiceProxy，不进仪表） |
| `onMapMatchingInfoUpdated` | 10 | `a(angle, speedKmh, speedLimit)` | 罗盘（只取角度，车速/限速被忽略） |
| `ClusterEvent` 路线规划/重算 | — | `a(status)` / `b(status)` | 计算中/重算中/结束 |

关键细节（`b.java:280-291`）：

```java
int remainDistance = turnInfo.getRemainDistance();
int turnKind = turnInfo.getTurnKind();
if (remainDistance >= 2000) {
    turnKind = 1;          // 距路口 >=2km 时强制显示“直行”
}
this.l.a(turnKind, turnInfo.getNextRoadName(), remainDistance);
```

> Reborn 若照搬原厂体验，应保留这个“>=2km 显示直行”的降噪规则。

### 3.2 实现类

`IClusterInfoHandler` 的唯一实现是 `common/integration/c/d.java`
（`SU2HUDController`），在 `IntegrationManager` 构造时创建，
并在导航引擎初始化完成后由 `business/b/d.java:316` 调用 `IntegrationManager.b().g().a()` 启动。

它把回调转成 HSAE 语义：

| 回调 | 处理 |
|---|---|
| 转向 | 环岛类 `turnKind >= 69` 先 `+= 21`（69..76 → 90..97），再进 `convertMapAutoTypeToDisplayType` |
| 行程 | 距离/时间格式化成 `updateRouteInfo(0, dist, hour, min, etaFormat, destName)` |
| 罗盘 | 车头角/目的地方位角转 22.5° 档位，仅在 displayType 为 8 或 2 时刷新 |
| 结束 | `GuidanceQuit` → `displayType=3`；计算中 → 9；重算中 → 10 |

### 3.3 写 Binder

`NaviClusterUpdater` 只做两件事：

```java
// TBT
navigation.cluTbtControl(displayType, sideStreet, direction,
                         distVal, combinedSideStreet, scale, distToTurn);

// 行程
navigation.setNaviEstDist(distF, unit, hour, min, azimuth,
                          distI, estimTimeFormat, estimTimeType, estPointType);
```

文本行走 `Vehicle.sendInfoToCluster((byte) 6, destName)`。

## 4. 事务号与 Parcel 布局（权威）

来自 `com/hsae/autosdk/navigation/INavigation$Stub` 与 `IVehicle$Stub`，
与 `adbridge-custin` 的布局逐字节一致。

### 4.1 `INavigation` transact 1 `cluTbtControl`

```
writeByte(displayType)
writeInt(sideStreet)          // 常量 15
writeByte(direction)          // 罗盘/目的地旗用；箭头为 0
writeInt(distVal)
writeByte(combinedSideStreet) // 常量 15
writeByte(scale)              // 0=米, 1=公里
writeByte(distToTurn)         // 公里一位小数
```

### 4.2 `INavigation` transact 6 `setNaviEstDist`

```
writeByte(distF)              // 公里小数位
writeByte(unit)               // 0=米, 1=公里
writeByte(hour)
writeByte(minute)
writeByte(azimuth)            // 原厂恒 0
writeInt(distI)
writeByte(estimTimeFormat)    // 原厂恒 1
writeByte(estimTimeType)      // 1=到达时刻, 2=剩余时长
writeByte(estPointType)       // 原厂恒 0
```

### 4.3 `IVehicle` transact 46 `sendInfoToCluster`

```
writeByte(type)               // 原厂恒 6
writeString(text)             // 目的地名；退出时空串
```

### 4.4 原厂未使用的事务

| 事务 | 原厂 | 说明 |
|---|---|---|
| 2 `setHuLanguageInfo` | ❌ | custin 用它发 `{0,0,0,1,1}` 当“接管”，语义存疑（官方名是语言信息） |
| 3 `setDisplayTG` | ❌ | custin 用它发 `(true,100)` 当“接管”，原厂完全不用 |
| 5 `setNaviSpd` | ❌ | 原厂不写限速圆牌；custin 的 tx5 仍是目前唯一验证过的限速写法 |
| 8-11 `updateAdasMap*` | ❌ | 本包内无调用方 |
| 12 `setNaviCameraAlertSettingStatus` | 仅 MnSoft 原生回调 | 相机提醒设置，不是限速 |
| 14 `sendClusterADASParser` | 仅 MnSoft 原生回调 | ADAS 自定义载荷，非导航 TBT |

### 4.5 原厂的第二条仪表通道：ADAS 载荷

`libMapAutoToADAS.so`（MnSoft）里有完整的 `AdasManager`：

```
sendPosMsg / sendSegMsg / makeMetaMsg / sendProLongMsg / sendProShortMsg
makeCurveMsg / makeRangeEvent / makeTrafficEvent / makeTunnelEvent / ...
```

这些消息不在 Java 层调用 `updateAdasMap*`，而是打包成 `byte[] + type`
经 `MapAutoToNaviService.sendClusterADASParser` → `INavigation` transact 14 下发。
Java 层只特判了 `type == 407`（相机提醒设置），其余全部走 transact 14。

> 这说明原厂仪表除了 TBT 还有一条独立的 ADAS/电子地平线通道。
> 原方案 11 §1.2 决定不做；**现已改为可选实验特性**（`KEY_CLUSTER_ADA_ENABLE`，
> 默认关闭），见 §4.6 与 16 号文档。

### 4.6 ADAS 线格式位布局（Ghidra 还原，Reborn 已实现可回放）

`AdasManager` 经 `sendMsg(type, byte[8], 8)` 发射 8 字节位域消息，
type 映射（`sendMsg` 内）：`0x101`=Position(458)、`0x102`=Segment(202)、
`0x103`=Stub(203)、`0x104`=ProfileShort(204)、`0x105`=ProfileLong(205)、
`0x106`=Meta(459)、`0x100`/`0x109`=事件。

Reborn `cluster/AdasPayloadCodec.kt` 已还原并测试以下布局（LSB-first）：

| 类型 | 位偏移（LSB-first） | 语义（Ghidra 推导，待实车标定） |
|---|---|---|
| Position 458 | f0[0..4]车道 f1[5..7]路线 f2[8..15]偏航 f3[16..21]航向 f6[25..29]GPS质量 f8[32..39]高程 f11[44..46]卫星 f13[56..63]北向 | 车道/航向用 NaviState 真实数据 |
| Segment 202 | f0[0..4] f1[5..7]类型 f2[8..15]段ID f3[16..21]道路等级 f6[25..29]限速码 | 限速=roadSpeedLimit/5 |
| ProfileShort 204 | f3[16..21]曲率 f5[24..29]间隔 f10[42..47]分隔带 f15[59..63]区间类型 | 弯道/区间 |
| ProfileShort(弯道) | f0[0..4]曲线类型 f3[16..21]曲率码 f5[24..29]区间距离 f15[59..63]分隔带 | makeCurveMsg，TBT 转向推导曲线类型 |
| ProfileLong 205 | 同 Short + f11[42]扩展位 | 长区间 |
| Meta 459 | f0[0..1]序号 f2[5..7]帧标志 f3[8..15]时间戳高 f4[16..19]时间戳低 | 每条消息流的前导帧 |

**Tunnel（type 207）不是独立线格式**：它是内部 `QList<_stTunnelInfo>`
（`makeTunnelEvent` / `updateTunnelInfo`），用于门控哪些隧道段进入
Segment/Profile 通道，最终仍经 202/204/205 发射。HSAE 适配层里
`updateTunnelInfo` 是空实现，隧道信息不进仪表（§3/§4 已述）。

真实数据接入见 `cluster/AdasHorizonPublisher.kt`（Position/Segment/Meta 三帧，
受 `adasEnabled` 门控），实车标定入口见 16 号文档「ADAS 标定」。

## 6. 距离/时间格式（原厂算法）

### 6.1 TBT 距离（`makeILSignal115(int turnType, int meters)`）

```
>= 100000 m : dist = meters / 1000,        scale = 1, frac = 0
>= 1000 m   : r = meters + 50;
              dist = r / 1000,             scale = 1, frac = (r / 100) % 10
< 1000 m    : dist = meters,               scale = 0, frac = 0
```

例：1500 m → `dist=1, scale=1, frac=5`（仪表显示 1.5 km）。

### 6.2 行程剩余（`makeILSignal1E7`）

```
>= 100000 m : distI = meters / 1000, unit = 1, frac = 0
>= 1000 m   : r = meters + 50;
              distI = r / 1000,        unit = 1, frac = (r / 100) % 10
< 1000 m    : distI = meters,          unit = 0, frac = 0

hour = 剩余秒 / 3600
min  = (剩余秒 % 3600) / 60     // 或到达时刻的 HH:mm
estimTimeFormat = 1
estimTimeType   = 1（到达时刻）/ 2（剩余时长）
estPointType    = 0
```

### 6.3 罗盘方向

```
direction = ((byte)(((360 - bearing) / 22.5f) + 0.5f)) * 3
if (direction > 47) direction = 0
```

每档 22.5°，编码步长 3（0,3,6,…,45）。

## 7. 状态机（原厂）

```
displayType = 8   ── 罗盘/无引导（初始值）
     │  turn status = 1 且 turnType != 0
     ▼
displayType = 65..72 / 96..  ── 转向箭头
     │  turn status = 0
     ▼
displayType = 8   ── 回到罗盘

turn status = 2  → 10（重新规划）
turn status = 3  → 9（计算中）
turn status = 4  → 3（导航结束）
```

`displayType` 是 `NaviClusterManager` 的静态字段，TBT 与罗盘共用；
罗盘刷新只在 `displayType == 8 || 2` 时下发，避免覆盖箭头。

## 8. 与 custin 实现的差异

| 项 | 原厂 ADAS | adbridge-custin | Reborn 应采用 |
|---|---|---|---|
| 接管握手 | 不做 | `tx3(true,100)` + `tx2{0,0,0,1,1}` | **先不做**；实车不显示再补，且需 A/B 验证 tx2 是否真是开关 |
| 限速 | 不写 | `tx5` 20–150 钳制 | 用 custin 写法（目前唯一验证过） |
| 行程 `estimTimeType` | 1 或 2 | 恒 1 | 按是否有到达时刻选择 |
| 文本行 | 只发目的地名（type 6） | 红绿灯前缀 + 路名 | 沿用 custin（信息更全），但需注意与原厂抢写 |
| 导航结束 | `displayType=3` | `displayType=8` + 清文本 | 用 3 结束、8 恢复罗盘，二者都发更稳 |
| 图标 | Baidu 枚举 → HSAE 码 | 高德 ICON → HSAE 码 | 见 §5 与 `12` §6 |

## 9. 三包之间的 IPC（与仪表无关，但会影响“谁在写仪表”）

### 9.1 DuerOS → ADAS（语音控制）

- 绑定 `com.baidu.NaviControllerService`（action 同名），
  通过 Binder 收发 `(type, errorNo, requestId, func, params)`。

- ADAS 侧实现：`com/baidu/mapauto/common/h/a/a.java`（`DuerOSReceiver`）
  把 `fun_navi_*` 映射成内部 `com.baidu.mapauto.*` 广播，
  再由 `b.java`（`DuerOSResponser`）回 `sendResponse`。

### 9.2 ADAS → DuerOS（定位/行程广播）

## 10. 对 Reborn 的直接结论

### 10.1 图标表（可落地）

```
Amap ICON → HSAE displayType
  2 直行        → 65
  3 左转        → 70
  4 右转        → 67
  5 左前方      → 71
  6 右前方      → 66
  7 左后方      → 69
  8 右后方      → 68
  9 掉头        → 72
 10 直行通过    → 65
 16 靠左        → 71
 其它          → 255（未标定不盲发）
```

待标定：11/12（进出环岛）、14（收费站）、17（靠右）、20（驶出匝道）。

> 说明：上表的 HSAE 码语义由原厂 APK 独立确认；**左侧高德 ICON 编号来自
> custin 的实车标定**（其注释逐项标了“实测”）。两者在 2/3/4/5/6/7/8/9 八个值上
> 完全自洽，可信度高；但首次上车仍建议用一次真实导航核对 ICON 与屏幕箭头。

### 10.2 接管

原厂不做握手，直接写 transact 1 就能让仪表从罗盘切到箭头。
Reborn 第一版应**先只写 transact 1/5/6/46**；如果实车不显示，再补 custin 的 tx3/tx2。
不要默认 tx2 是“导航模式开关”——官方方法名是 `setHuLanguageInfo`。

### 10.3 限速

原厂不写限速，不代表 HSAE 不支持。custin 的 tx5 是唯一有实车依据的写法，
Reborn 按 `12` §4.3 执行，并保留 20–150 / 每秒 ≤20 的钳制。

### 10.4 单写者

原厂 ADAS 只要在前台导航就会写仪表。Reborn 接管期间必须保证
百度导航没有在写，否则会互相覆盖（HSAE 没有来源仲裁）。
设置开关关闭或 3s 无高德广播时必须执行交还序列。

### 10.5 权限风险（新增）

原厂 ADAS 是 `android.uid.system`。Reborn 是普通应用，
`INavigation` 是否校验调用方 uid **尚未验证**。上车第一件事：
在 Reborn 里打一条 `transact(1)` 的探针，捕获 `SecurityException`；
若被拒，只能走系统应用/平台签名路线，不能靠反射绕过。
