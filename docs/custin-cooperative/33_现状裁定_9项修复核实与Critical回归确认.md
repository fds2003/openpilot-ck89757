## 三、Critical 回归（本轮最重要发现，独立确认 V-32 F-32-01 并加严）

### 3.1 现象

```python
# C3:selfdrive/carrot/amap_navi.py:294-302（当前工作区）
ttc_list = []
for side in ("lb", "rb"):
  d = getattr(self.shared_data, f"main_{side}_drel", None)
  v = getattr(self.shared_data, f"{side}_vrel", None)
  if d is not None and abs(d) > 0 and v is not None and v < -0.1:
    ttc_list.append((abs(d) / 1000.0) / abs(v))
ttc = min(ttc_list) if ttc_list else 0.0        # ← 无"正在接近的后车" = 0.0
```

```python
# C3:selfdrive/controls/lib/desire_helper.py:955-963（当前工作区）
behind_ttc = amapNavi.lidarBehindVdistTime if amap_alive else 0.0
rear_conflict = (behind_ttc <= 0.0) or (behind_ttc < ttc_threshold)
if rear_conflict:
  auto_lane_change_trigger = False
```

### 3.2 机理（为什么这是"关功能"，不是"更安全"）

`ttc_list` **只有在"后方存在正在接近的目标（`v < -0.1`）"时非空**。以下全部常见工况都会得到 `ttc = 0.0` → `rear_conflict = True` → 阻断：

| 工况 | `ttc_list` | 结果 |
| :--- | :--- | :--- |
| 后方空车道 | 空 | 0.0 → 阻断 |
| 后车同速并行 | 满足 `v < -0.1` 为假 → 不入列表 | 0.0 → 阻断 |
| 后车正在远离 | 同上 | 0.0 → 阻断 |
| 后车距离 > 雷达量程（d=None） | 空 | 0.0 → 阻断 |
| 后方恰有车接近且 TTC ≥ 门限 | 非空 | **唯一放行组合** |

即"**只有在最危险的那一种情形下才允许变道**"，与设计意图完全相反。

### 3.3 比 V-32 描述更严重的一点

`desire_helper.py:1250-1258` 的执行期复检用的是同一判据：

```python
if (_ttc <= 0.0) or (_ttc < _thr):
    self.lane_change_state = LaneChangeState.off
```

因此在空车道工况下：**即使驾驶员手动打灯、状态机成功进入 `laneChangeStarting`，下一帧立刻被 abort 回 `off`**（`trigger_name = "rear ttc abort"`）。表现为"打了灯不动、指示灯闪一下就退出"，且会反复播报 `lane_change_audio(True, 6, 0)`。

> 换言之：R-31/V-32 讨论的"触发段阻断"只是第一层；**执行段的自杀式中止**使手动变道也不可用。V-32 用例 2/3 的矛盾（F-32-02）也由此得到解释——不存在能同时通过的版本。

### 3.4 一行修复（保留 fail-safe，恢复可用）

```diff
--- a/selfdrive/carrot/amap_navi.py
+++ b/selfdrive/carrot/amap_navi.py
@@
-    ttc = min(ttc_list) if ttc_list else 0.0
+    # 三态：有目标取最小 TTC；无目标 = 99.0（安全）；传感器不在线 = 0.0（未知 -> 阻断）
+    lidar_present = bool(getattr(self.shared_data, "lidar_l", False) or
+                         getattr(self.shared_data, "lidar_r", False))
+    ttc = min(ttc_list) if ttc_list else (99.0 if lidar_present else 0.0)
```

消费端（`:957` 与 `:1255`）无需改动：`99.0` 不触发阻断，`0.0` 触发阻断，语义正好对齐。

> 若要更严谨（区分"雷达在线但无目标"与"雷达在线但该侧无数据"），应新增 capnp 有效性位（`leftRearTtcValid @17 : Bool`），但这需要重生成生成物——正好与 M-17 一并做。

```text
   要求"空车道放行、雷达断流阻断"同时成立，并入库脚本与原始输出
```
