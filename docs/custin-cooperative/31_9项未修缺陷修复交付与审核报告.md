### 2.1 M-16：SPEED_LIMIT 指令消费闭合（Major）

**问题**：车机 `RelayEngine.kt:185/249` 发送 `SPEED_LIMIT` 指令，C3 `carrot_serv.py:354-358` 的 `command_handlers` 只有 `DETECT`，指令落入 `handler=None` 死信路径。

**修复方案**：
1. 新增 `_handle_speed_limit_command(self, xArg)` 方法，解析 `int(xArg)` 并校验 `0 ≤ v ≤ 160`：
   - 合法时写入 `self.nRoadLimitSpeed` 与 `self.nRoadLimitSpeed_last`，记录 info 日志
   - 非法（非整数或超范围）时阻断指令、记录 warning 日志、保持当前值不变
   - **禁止沿用存量 `_handle_detect_command` 的 `except ValueError: pass` 静默吞错模式**（避免 fail-open）
2. 在 `command_handlers` 字典注册 `"SPEED_LIMIT": self._handle_speed_limit_command`

**落盘代码**（`carrot_serv.py`）：
```python
def _handle_speed_limit_command(self, xArg):
  try:
    speed_kph = int(xArg)
  except (ValueError, TypeError):
    print(f"[SPEED_LIMIT] invalid arg '{xArg}', blocked, nRoadBlastLimitSpeed unchanged={self.nRoadLimitSpeed}")
    return
  if speed_kph < 0 or speed_kph > 160:
    print(f"[SPEED_LIMIT] out-of-range {speed_kph} (expect 0~160), blocked, nRoadLimitSpeed unchanged={self.nRoadLimitSpeed}")
    return
  self.nRoadLimitSpeed = speed_kph
  self.nRoadLimitSpeed_last = speed_kph
  print(f"[SPEED_LIMIT] accepted, nRoadLimitSpeed={self.nRoadLimitSpeed}")
```

```python
command_handlers = {
  "DETECT": self._handle_detect_command,
  "SPEED_LIMIT": self._handle_speed_limit_command,
}
```

**安全审查**：
- 非法参数阻断而非 `pass`，不引入 fail-open ✓
- 自动复用 `:352-353` 的序号门控，无需在 handler 内重复实现 ✓
- `nRoadLimitSpeed` 在 `:1009/:1119` 参与 `min_desire_speed_kph` 计算，更新链路正确 ✓

### 2.3 M-18：客户端清理线程容错（Minor）

**问题**：`amap_navi.py:1551` 的 `_clean_clients_thread` 无 try/except，`info["last_seen"]` 键漂移会静默打死线程。

**修复方案**：在 `while True:` 循环体内整体包裹 `try/except (KeyError, RuntimeError, Exception)`，异常时记录日志并 `continue` 保持线程存活。`time.sleep(0.2)` 在 try/except 之外确保异常后仍执行等待。KeyError 时将该客户端标记为超时（从 `self.clients` 剔除、`client_active[ip] = False`）。

**落盘代码**（`amap_navi.py:1551-1579`）：
```python
def _clean_clients_thread(self):
  while True:
    try:
      now = time.time()
      with lock:
        active_clients = {}
        for c_ip, c_info in self.clients.items():
          try:
            if now - c_info["last_seen"] < 1.0:
              active_clients[c_ip] = c_info
          except KeyError:
            print(f"[Client Timeout] ip={c_ip}, last_seen missing, marked timeout")
            if c_ip in self.client_active:
              self.client_active[c_ip] = False
        for ip, info in self.clients.items():
          if ip not in active_clients and ip in self.client_active:
            last = info.get("last_seen", 0)
            dt = now - last
            print(f"[Client Timeout] ip={ip}, last_seen={last:.3f}, now={now:.3f}, dt={dt:.3f}s")
            self.client_active[ip] = False
        self.clients = active_clients
        if self.clients:
          ext_state = len(self.clients)
        else:
          ext_state = 0
          self.shared_data.ext_blinker = BLINKER_NONE
        if self.lane_online:
          ext_state += 1
        self.shared_data.ext_state = ext_state
    except (KeyError, RuntimeError, Exception) as e:
      print(f"[_clean_clients_thread] exception: {e}, continue")
    time.sleep(0.2)
```

**安全审查**：
- 线程 daemon 属性不变，主进程退出时自动终止 ✓
- KeyError 时客户端被标记超时（剔除），禁止保留为活跃（避免 fail-open）✓
- 异常隔离：客户端 A 异常不影响客户端 B 的清理判断 ✓
- `time.sleep(0.2)` 在 try/except 之外，异常后仍执行等待 ✓

**负向测试用例**：
| 场景 | 预期 |
|:---|:---|
| info 缺失 last_seen 键 | 捕获 KeyError，客户端标记超时，线程继续 |
| 遍历时另一线程修改字典触发 RuntimeError | 捕获异常，跳过本次迭代，下一轮重试 |
| 连续注入多次异常 | 线程持续存活 60s 以上不退出，日志可见每次异常 |
