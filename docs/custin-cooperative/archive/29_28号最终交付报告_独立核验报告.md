## 三、残留问题（必须处理或撤回宣称）

### F‑29‑01（Major · 安全）雷达缺失时 TTC 仍 fail‑open
- **位置**：`amap_navi.py:295-305` 与 `desire_helper.py:1244-1251`
- **机理**：`ttc_list` 为空（无雷达目标、雷达掉线、后车静止）时输出 `99.0`；`desire_helper` 的主门禁与 P‑4 执行期门禁均写作 `0.0 < ttc < thr`，`99.0` 直接放行。`amapNavi` 消息由 `carrot_man`（`always_run`）持续发布，`amap_alive` 几乎永远为真 → **"消息失活才阻断"的 fail‑safe 形同虚设**。
- **影响**：4 路外挂激光雷达任一环掉线（线缆/供电/网络）时，后车快速逼近仍可发起或继续变道。
- **修复建议**（二选一）：
  ```python
  # A. 在 public_amap_navi 中用雷达存在标志门控
  lidar_present = bool(self.shared_data.lidar_l or self.shared_data.lidar_r)
  msg.amapNavi.lidarBehindVdistTime = float(ttc if lidar_present and ttc_list else 0.0)
  msg.amapNavi.overtakeMode = self.shared_data.overtake_mode
  ```
  ```python
  # B. 增加显式有效性位（capnp 尾插 @17）
  lidarTtcValid @17 : Int32;
  # 消费端：rear_conflict = (not ttc_valid) or (behind_ttc <= 0.0) or (behind_ttc < thr)
  ```
- 若"未装雷达用户"需要放行，应通过 `Params` 显式开关声明，默认走安全侧。

### F‑29‑02（Major · 功能）`CANCEL_LANE_CHANGE` 仍是空操作（27 号 C‑08 未修）
- **位置**：`amap_navi.py:1013` 只把命令字符串映射为 `"CANCEL"`；`desire_helper.py:506` 仅识别 `"LANECHANGE"` / `"OVERTAKE"`；`carrot_serv.py:354-360` 的 `command_handlers` 只有 `"DETECT"`。
- **影响**：车机端"人工复位/紧急撤销变道"按钮下发后，C3 **无任何响应**。
- **修复**：在 `desire_helper` 命令分支增加：
  ```python
  elif carrotMan.carrotCmd == "CANCEL":
    self.carrot_lane_change_count = 0
    self.lane_change_state = LaneChangeState.off
    self.lane_change_direction = LaneChangeDirection.none
  ```

### F‑29‑03（Major · 功能）`SPEED_LIMIT` 无消费者
- **位置**：车机 `RelayEngine.kt:185-190`（`nudgeCruise`）与 `:249`（匝道限速）均发送 `cmd="SPEED_LIMIT"`；C3 全仓无该命令的处理器。
- **影响**：车机上的巡航增减、匝道平滑减速指令**全部无效**，但 UI 仍显示已同步。
- **修复**：在 `carrot_serv.py` 的 `command_handlers` 增加 `"SPEED_LIMIT"` handler，或从车机端撤回该功能入口。

### F‑29‑04（Minor/Major · 安全一致性）重放包仍可改写 `overtake_mode` / `remote_cmd`（27 号 C‑09 未修）
- **位置**：`amap_navi.py:1009-1020`
- **机理**：`idx > cmd_index` 的判断只保护了 `cmd_index` 自增本身；紧随其后的 `remote_cmd`、`overtake_mode` 赋值**在门控之外无条件执行**。白名单内的旧包/重放包虽不会让 `carrot_man` 触发新指令（`cmd_index` 未变），但可把 `overtake_mode` 改回激进值（0），影响下一次正常指令。
- **修复**：把 `remote_cmd/remote_arg/overtake_mode` 的赋值整体移入 `if idx is not None and idx > self.shared_data.cmd_index:` 分支内。

### F‑29‑05（Minor）序号门控导致车机重启后指令锁死
- **位置**：车机 `CarrotUdpClient.kt:41` `sequenceId = AtomicInteger(1)`（进程内）；C3 `cmd_index` 从不复位。
- **影响**：车机 App 重启后序号从 1 开始，C3 只接受 `idx > 历史最大值`，导致**指令被静默丢弃**，直到序号重新超过历史值。
- **修复**：`app_ip` 变化或超过 5 s 无指令时复位 `cmd_index = -1`。

### F‑29‑06（Minor）"领航已退出"语音可能重复播报
- **位置**：`desire_helper.py:1359` 新增立即播报；`:1363-1366` 原有 `atc_cancel_delay == 0` 时再播一次。
- **影响**：驾驶员接管时同一句话播两遍（0 s 与约 2 s 各一次）。建议只保留其一。

### F‑29‑07（Minor）JSONObject 重载的默认值 999.0 会被换算成 0.999 m
- **位置**：`CarrotTelemetryParser.kt:123-124`：`json.optDouble("lb_drel", 999.0)` → `parseDistanceMeter(999.0)` → `999/1000 = 0.999` → 误判为"后车 1 m"而永久阻断。
- **现状**：该重载当前**未被调用**（`RelayEngine.kt:215` 只调用字符串重载），属潜伏缺陷。
- **修复**：默认值改为 `-999999.0`（与流式重载一致），或对 `999.0` 做哨兵特判。

### F‑29‑08（Minor）`parseDistanceMeter` 的 `>100` 启发式有反例
- 若上游传入**米制 120.5 m**，会被 `/1000` 变成 0.12 m → 误阻断。后装微激光雷达量程通常远小于 100 m，实际风险低，但建议在协议层固定单位（推荐统一米制）并在注释中写明量程前提。

### F‑29‑09（观察）验收手册第 2 步的本机回环测试可能被白名单丢弃
- 28 号五节第 2 步向 `127.0.0.1:7705` 发包；若 `app_ip` 已由发现流程设置为车机 IP，`_update_command` 会因 `ip != app_ip` 直接 `return`，测试看似"发成功"实则被丢弃。建议测试前先清空 `app_ip`，或临时放行 `127.0.0.1`。

### F‑29‑10（文档）"全部遗留问题 100% 修复"与事实不符
- 26 号提出、27 号台账列明的 `C‑08`（`CANCEL` 无消费者）、`C‑09`（重放改写 `overtake_mode`）在本提交中**未修复**；`SPEED_LIMIT` 无消费者亦未处理。建议将报告标题改为"5 项阻断级缺陷 100% 闭环 + 4 项遗留项待处理"，避免验收口径失真。
