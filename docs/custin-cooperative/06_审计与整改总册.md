## 3. 最终裁定

1. **当前代码为准**：端口、载荷、字段以 `03_通信契约与功能边界.md` 与代码为准。
2. **单进程模型**：`carrot_man` 独占 `amapNavi` 与 UDP；`lane_runner` 只发本地 UDP。
3. **两代协议并存**：7706/7705 两套入口，遥测统一 7706。
4. **安全边界**：车内局域网，不引入完整 HMAC；以源信任 + 字段校验 + 序号为主。
5. **残留**：实车未验证；遥测字段未全量解析；`blind_l/r` 未单独合成。

## 4. 经验教训

1. **文档会漂移**：协议类文档必须标注"以代码为准"的核验日期与证据。
2. **端口表最容易写反**：把"谁监听、谁发送"分开写，避免方向歧义。
3. **单发布者是硬约束**：任何新增进程先确认是否触碰 `PubMaster`。
4. **安全加固要验证链路**：loopback 绑定在双机部署中等于断网。
5. **审计报告之间也会冲突**：以可复现的代码证据裁决，不以文档互相引用裁决。
6. **"已修复"必须有测试**：TDD 红→绿是唯一可信的闭环证据。
