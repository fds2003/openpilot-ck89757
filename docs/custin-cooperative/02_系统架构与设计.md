## 4. 关键设计决策

### 4.1 端侧 ONNX 移到 C3

车机 i.MX6 跑 416×416 模型不可靠（发热、掉帧、倒车影像卡死）。
`lane_runner` 使用 C3 摄像头与算力，结果经本地 UDP 4213 交回 `amap_navi`。

### 4.2 单一发布者

`amapNavi` 的发布者只能是 `carrot_man` 内嵌的 `AmapNaviServ`。
`lane_runner` **不创建** `PubMaster(['amapNavi'])`，避免 `MultiplePublishersError`。

### 4.3 协同模式

`CarrotCooperativeMode`（默认 true）：

- 车机在线（发现探针 15s 内有更新）→ C3 不发布自主转向类型；
- 车机失联 → 回退 C3 自主 ATC；
- 只抑制 `atc_type`，保留转弯/匝道速度规划。

### 4.4 两代协议并存

C3 同时保留 7706（原版 `carrotCmd`）与 7705（Reborn `cmd`）入口；
遥测统一发 7706。两代车机不能混用。

### 4.5 源信任

未配 `CarrotUdpAllowedIps` 时仅学习同网段；配置后进入严格模式；
本地 IP 未知时 fail-closed。

## 6. 部署拓扑

```
车内热点（WPA2）
├─ 车机  192.168.x.A   App + 高德
├─ C3    192.168.x.B   carrot_man / lane_runner
└─ 其它设备（如 adbridge）
```

- 车机与 C3 必须同网段，或显式配置 `CarrotUdpAllowedIps`。
- C3 管理端口仅 loopback，经 SSH 隧道访问。
