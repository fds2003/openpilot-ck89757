# 15 L1 共存切换实施方案

> 目标：用高德地图导航，同时保留原车功能；三个原厂包一个都不删。
> 适用范围：库斯途 KU 车机（Android 4.4.3 / API 19 / armeabi-v7a）
> 关联：`11_仪表移植方案.md`、`12_仪表投影布局对照.md`、`13_原厂三包与仪表投影分析.md`、`14_原厂三包功能全景与架构拆解.md`
> 基线：2026-11-07

---

## 1. 目标与边界

### 1.1 目标

```
高德车机版（导航）
      │  AUTONAVI_STANDARD_BROADCAST_SEND
      ▼
Reborn（解码 + 仪表投影 + C3 协同）
      │  HSAE Binder
      ▼
原厂仪表
```

- 高德导航时，Reborn 接管仪表，显示高德 TBT/限速/行程/路名。
- 百度 ADAS 保留，作为回退；它导航时仍可自己写仪表。
- DuerOS 保留，语音导航默认切到高德。
- 百度地图车机版可保留或禁用，不影响另外两个包。

### 1.2 不做什么

- 不修改 DuerOS / ADAS / 百度地图的 APK。
- 不做同包名替换、不申请 `android.uid.system`。
- 不做 BlueLink、ADAS 外部广播的兼容层（那是 L2）。
- 不实现 DuerOS 的 `NaviControllerService` 兼容 Binder（切默认导航即可）。
- 不改 C3（除非后续要用 C3 车道数据补仪表）。

### 1.3 成功标准

1. 高德导航时，仪表完整显示箭头、米数、限速、行程、路名。
2. 语音“导航去某地”由高德执行，不由百度 ADAS 执行。
3. 高德退出后仪表恢复罗盘、文本清空。
4. 只开百度 ADAS 时，Reborn 不写仪表。
5. 关闭 Reborn 总开关时，transport 调用次数为 0。
6. 连续 30 分钟无 ANR、无 Binder 异常刷屏。

## 2. 总体架构

```
┌────────────────────── 车机 ──────────────────────┐
│                                                   │
│  高德车机版 ──广播 10001/13012──► Reborn          │
│      ▲                              │            │
│      │ RECV 控制命令                 │ HSAE Binder │
│  DuerOS（默认导航=Amap）             ▼            │
│                                  原厂仪表          │
│  百度 ADAS（保留，回退）──Binder──► 原厂仪表       │
│                                                   │
│  百度地图车机版（可禁用，无耦合）                   │
└───────────────────────────────────────────────────┘
```

关键原则：

- **单一写者**：同一时间只允许一个导航 App 写仪表。
- **失败静默**：仪表模块任何异常都不影响导航、C3 协同和变道主链路。
- **默认关闭**：`cluster_enable` 默认 `false`，实车验证后再打开。

## 3. 工作分解

| 工作块 | 内容 | 交付物 | 预估 |
|---|---|---|---|
| A. 配置与切换 | 切 DuerOS 默认导航；确认高德版本；决定百度地图去留 | 可复现步骤 | 0.5–1 天 |
| B. Reborn 解码补齐 | 路名、路线剩余、ETA、红绿灯、导航状态 | `NaviState` + Decoder | 1–2 天 |
| C. Reborn 仪表模块 | HSAE Binder、映射、发布器、设置 | `cluster/` 新包 | 3–5 天 |
| D. 单写者仲裁 | 高德导航时写；退出/超时交还；百度导航时不抢 | 状态机 + 诊断 | 1–2 天 |
| E. 设置与 UI | 总开关、分通道开关、服务状态、最近发送 | 设置页 | 1–2 天 |
| F. 验证 | 单测 + 实车 | 验收记录 | 1–2 天 |

合计约 **8–14 人天**。

## 4. 配置与切换

### 4.1 把 DuerOS 默认导航切到高德

DuerOS 的默认导航是持久化枚举，值只有三个：

```
Baidu / Amap_Lite / Amap
```

存储位置：

```
包名：com.baidu.che.codriver
文件：SharedPreferences "prefs_amap"
键：  key_default_navi_app
```

三种切换方式，按优先级：

#### 方式 1：DuerOS 设置页

优先找“默认导航/导航应用”入口。有 UI 就不需要 root。

#### 方式 2：DuerOS 第三方 SDK（推荐）

`CoDriverService` 的 `map.tool` 命令：

```
cmdType = map.tool
param   = fun_navi_set_default_app
data    = Amap
```

这是 DuerOS 自己暴露的接口，不需要 root。切换后：

- `AmapHeartbeat` 启动，开始 5s 心跳；
- 语音导航命令改发 `AUTONAVI_STANDARD_BROADCAST_RECV`。

验证日志：

```
save default navi app: Amap
amap_heartbeat start
```

#### 方式 3：root 改 SharedPreferences

```
/data/data/com.baidu.che.codriver/shared_prefs/prefs_amap.xml
```

写入 `key_default_navi_app=Amap`，杀掉 DuerOS 进程后重启，避免内存旧值覆盖。

### 4.2 确认高德版本契约

高德必须能发：

```
AUTONAVI_STANDARD_BROADCAST_SEND
  KEY_TYPE=10001   限速 / TBT / 路名 / 路线剩余 / 红绿灯
  KEY_TYPE=13012   车道 JSON
```

并能收：

```
AUTONAVI_STANDARD_BROADCAST_RECV
  10009 开始导航
  10010 退出导航
  10027 缩放 / 路况 / 视角
  10034 打开高德
  10048 昼夜模式
```

如果高德版本不支持 13012，只影响车道推荐，不影响仪表 TBT。

### 4.3 百度地图车机版

它与另外两个包无直接 IPC。L1 阶段：

- **保留**（最稳），或
- `pm disable-user --user 0 com.baidu.BaiduMap.auto`（有 root 更稳）。

不影响 DuerOS 和 ADAS。

### 4.4 桌面/方向盘“导航”键

确认它启动的是百度 ADAS 还是高德。如果是 ADAS：

- 改 launcher 快捷方式指向高德，或
- 增加一个高德快捷方式。

这是车机配置，不是 APK 开发。

## 5. Reborn 解码补齐

### 5.1 `NaviState` 新增字段

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `routeRemainDistance` | Int | `ROUTE_REMAIN_DIS` | 行程剩余米数 |
| `routeRemainTime` | Int | `ROUTE_REMAIN_TIME` | 剩余秒数 |
| `etaText` | String | 由剩余时间计算 | 可选，文本行用 |
| `currentRoadName` | String | `CUR_ROAD_NAME` | 已有字段，补赋值 |
| `nextRoadName` | String | `NEXT_ROAD_NAME` | 已有字段，补赋值 |
| `trafficLightSeconds` | Int | 10001 / 10019 / 10020 | 已有字段 |
| `trafficLightStatus` | Int | 同上 | 已有字段 |

### 5.2 Decoder 规则

- **10001**：读 `LIMITED_SPEED`、`CAMERA_SPEED`、`SEG_REMAIN_DIS`、`ICON`、
  `ROUTE_REMAIN_DIS`、`ROUTE_REMAIN_TIME`、`NEXT_ROAD_NAME`、`CUR_ROAD_NAME`、
  `redLightCountDownSeconds`、`trafficLightStatus`。
- **13012**：保持现有车道 JSON 解析。
- **10019 / 10020**：保留兼容。
- **`EXTRA_STATE`**：
  - `9` / `0`：导航结束 → `navValid=false`；
  - `8`：开始导航 → `navValid=true`。
- **3s 无广播**：`navValid=false`（沿用现有 `getFreshNaviState`）。

### 5.3 TDD 用例

先写测试，再改实现：

- `AmapBroadcastDecoderTest`
  - 10001 路名/路线剩余/红绿灯；
  - `EXTRA_STATE=9/0` 结束；
  - `EXTRA_STATE=8` 开始；
  - 3s 超时失效；
  - 13012 车道 JSON。

## 6. Reborn 仪表模块

### 6.1 包结构

```
tech.touka.amapnavi.cluster/
├── ClusterTransport.kt      // 接口：sendTbt/sendSpeed/sendEst/sendText/clear
├── HsaeClusterTransport.kt  // 反射 ServiceManager + Parcel transact 1/5/6/46
├── ClusterFrame.kt          // 一帧要发的 4 类内容
├── ClusterMapper.kt         // 纯 Kotlin：NaviState -> ClusterFrame
├── ClusterPublisher.kt      // 去重/节流/保活/3s 超时/交还
├── ClusterSettings.kt       // 读 UserSettingsRepository
└── ClusterState.kt          // RELEASED / ACQUIRING / ACTIVE / RELEASING
```

### 6.2 Transport 布局（权威）

来自 `INavigation$Stub` / `IVehicle$Stub`，与 `adbridge-custin` 逐字节一致。

#### TBT：`INavigation` transact 1

```
writeByte(displayType)
writeInt(15)                 // sideStreet
writeByte(direction)         // 罗盘/目的地旗用；箭头为 0
writeInt(distVal)
writeByte(15)                // combinedSideStreet
writeByte(scale)             // 0=米, 1=公里
writeByte(distToTurn)        // 公里一位小数
```

#### 限速：`INavigation` transact 5

```
writeByte(0)  // overSpdAlarm
writeByte(0)  // nonSpdTrap
writeByte(0)  // warningZone2
writeByte(0)  // warningZone
writeByte(0)  // warningZone3
writeByte(0)  // curveWarning
writeByte(1)  // spdLimitType
writeByte(0)  // spdLimitUnit
writeByte(1)  // spdInfoType
writeByte(v)  // spdLimit，必须最后
```

钳制：`20..150`，每秒变化 ≤ 20。

#### 行程：`INavigation` transact 6

```
writeByte(distF)             // 公里小数
writeByte(unit)              // 0=米, 1=公里
writeByte(hour)
writeByte(minute)
writeByte(0)                 // azimuth
writeInt(distI)
writeByte(1)                 // estimTimeFormat
writeByte(estimTimeType)     // 1=到达时刻, 2=剩余时长
writeByte(0)                 // estPointType
```

#### 文本：`IVehicle` transact 46

```
writeByte(6)
writeString(text)
```

### 6.3 Mapper

#### 图标表（已定案）

```
Amap ICON -> HSAE displayType
  2 / 10 / 18 / 19 -> 65   直行
  3                -> 70   左转
  4                -> 67   右转
  5 / 16           -> 71   左前
  6                -> 66   右前
  7                -> 69   左后
  8                -> 68   右后
  9                -> 72   掉头
  其它             -> 255  不盲发
```

未标定：11/12（进出环岛）、14（收费站）、17（靠右）、20（驶出匝道）。

#### 距离格式

```
>= 100000 m : dist = m/1000,          scale=1, frac=0
>= 1000 m   : r=(m+50); dist=r/1000,  scale=1, frac=(r/100)%10
< 1000 m    : dist = m,               scale=0, frac=0
```

例：1500 m → `1.5 km`；800 m → `800 m`。

#### 行程格式

```
>= 100000 m : distI = m/1000, unit=1, frac=0
>= 1000 m   : r=(m+50); distI=r/1000, unit=1, frac=(r/100)%10
< 1000 m    : distI = m, unit=0, frac=0
```

#### 文本行

```
[红灯 18s] 路名
[绿灯 12s] 路名
[黄灯 3s]  路名
路名
```

- 路名优先 `nextRoadName`，空则 `currentRoadName`；
- 截断 24 字符；
- 红绿灯未知不加前缀。

### 6.4 Publisher

- 单线程 worker，队列只保留每类通道最新值；
- TBT 变化或 2s 保活，最小间隔 500ms；
- 限速 1s；行程 10s；文本 1s；
- 3s 无高德广播 → 交还；
- 交还序列：

```
INavigation 1：displayType=3     // 导航结束
INavigation 1：displayType=8     // 罗盘
IVehicle  46：byte 6 + ""        // 清空文本
```

- 总开关关闭 → transport 零调用；
- 每次 transact 独立 try/catch，失败只禁用该通道。

### 6.5 RelayEngine 接线

```
RelayEngine.start()
  -> 创建 ClusterPublisher
  -> scope.launch { naviStateFlow.collect { publisher.onNaviState(it) } }

RelayEngine.stop()
  -> publisher.release()
```

## 7. 单写者仲裁

### 7.1 L1 策略

```
仅当 cluster_enable=true 且 Amap 导航有效时，Reborn 才写仪表。
Amap 导航结束 / 3s 无广播 / 开关关闭 -> 交还。
```

### 7.2 场景表

| 场景 | 行为 |
|---|---|
| 高德导航中 | Reborn 写 |
| 高德退出 | 交还（3 → 8 → 清文本） |
| 只开百度 ADAS | Reborn 不写，ADAS 自己写 |
| 两个导航同时开 | 设置页提示“请只保留一个导航”，不自动仲裁 |

### 7.3 可选增强（L2 再做）

1. 监听 ADAS `com.baidu.mapauto.action.APP_FORGROUND`，判断前台（不判断是否导航）；
2. 以 DuerOS 同款协议绑定 ADAS `NaviControllerService`，发
   `fun_navi_navi_state {order:type_is_innavi}` 查询是否在导航。

前者简单但不准，后者准确但要实现 Binder 客户端。

## 9. 测试与验收

### 9.1 单测（TDD 必须）

- `ClusterMapperTest`：全部 ICON、距离格式、限速回退、文本行、未知码 255。
- `ClusterPublisherTest`（FakeTransport）：去重、节流、保活、3s 超时、开关关闭零调用、异常不崩溃。
- `AmapBroadcastDecoderTest`：10001 路名/路线剩余/红绿灯、EXTRA_STATE 结束、13012 车道。

### 9.2 实车验收

1. 高德导航 → 仪表出现箭头/米数/限速/行程/路名。
2. 1.5km 路口显示 `1.5 km`，800m 显示 `800 m`。
3. 左转/右转/掉头箭头方向正确。
4. 红绿灯文本行逐秒递减（如果高德提供）。
5. 退出高德 → 仪表恢复罗盘、文本清空。
6. 语音“导航去某地” → 高德收到 `AUTONAVI_STANDARD_BROADCAST_RECV`。
7. 只开百度 ADAS → 仪表正常，Reborn 不写。
8. 关闭 Reborn 总开关 → transport 零调用，百度可正常接管。
9. 连续 30 分钟无 ANR、无 Binder 异常刷屏。
10. 重启车机后状态正确。

### 9.3 回滚

- `cluster_enable=false`
- DuerOS 默认导航改回 `Baidu`
- 重新启用百度地图车机版（如果之前禁用）

## 11. 风险与前置验证

| 风险 | 影响 | 对策 |
|---|---|---|
| 普通应用写 `INavigation` 被拒 | 整个 L1 不成立 | 先打 `transact(1)` 探针，捕获 `SecurityException`；被拒则需系统应用/平台签名（L3） |
| DuerOS 设置页没有默认导航入口 | 切不了高德 | 用 `map.tool/fun_navi_set_default_app/Amap` 或 root 改 prefs |
| 高德版本不支持 13012 | 车道推荐缺失 | 不影响 TBT；如实标注 |
| 两个导航同时开 | 仪表互相覆盖 | 设置页提示；后续做 L2 仲裁 |
| 禁用 ADAS 后仪表停在旧帧 | 仪表冻结 | 禁用前 Reborn 发交还序列（L2 才涉及禁用） |
| 系统 OTA 恢复原厂包 | 配置被重置 | 记录切换步骤，OTA 后重做 |
| 高德不提供红绿灯/ETA | 文本行降级 | 文本行只显示路名；ETA 用剩余时间计算 |
| 不启动百度 ADAS 时天气不更新 | DuerOS 天气依赖有效经纬度，而这台车的定位来自 ADAS 的 `NAVI_GPS_CHANGED` | 加一个定位桥（从高德广播/系统定位发同名广播），或启用 DuerOS 自带定位；详见 §12.6 |

### 12.6 天气与 DuerOS 定位依赖（重要）

车机天气由 DuerOS 取回并广播，而 DuerOS 的天气请求要求有效经纬度：

```
ADAS（com.baidu.mapauto，图标名“百度地图”）
  → com.baidu.mapauto.action.NAVI_GPS_CHANGED (LAT/LON)
  → DuerOS LocationReceiver
  → LocationUtil.setCustomLatitude/Longitude
  → OutputDataService 发天气请求
  → com.hkmc.intent.action.weather_update
  → 车机桌面/天气组件
```

因此：

- **不启动 ADAS 时，DuerOS 可能拿不到定位，天气不更新**；
- 如果替换/禁用 ADAS，需要补一个定位桥：
  - 从高德广播或系统定位取经纬度；
  - 发 `com.baidu.mapauto.action.NAVI_GPS_CHANGED`，extras 至少包含
    `com.baidu.mapauto.gis.extra.LAT` / `LON`。
- 或者让 DuerOS 使用自身定位 SDK/系统定位（需验证 `LocationUtil.isSystemLocation()` 路径）。

> 这不是仪表链路的一部分，但属于“原车功能保留”的隐藏依赖，L1/L2 都要验证。
